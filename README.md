# Apollo Import GUI Prototype

Dieser Prototyp zeigt eine moegliche Desktop-GUI fuer die Erfassung neuer Artikel und erzeugt daraus die Importdateien als `.xlsx`.

Das Programm nutzt jetzt ein eigenes App-Logo aus `assets/apollo_import_logo.png` bzw. `assets/apollo_import_logo.ico`, das sowohl in der laufenden GUI als auch im Windows-`exe`-Build verwendet wird.

## Start

```powershell
python apollo_import_gui.py
```

Alternativ unter Windows:

```powershell
.\start_gui.bat
```

## Was die GUI kann

- Artikelnummer erfassen
- Zwei getrennte `Text Modul ID`s automatisch pro Artikel vergeben
  - eine fuer `Kurzbezeichnung`
  - eine fuer `Text`
- Kurztexte pro Sprache pflegen
  - Umlaute in Kurzbezeichnungen werden automatisch ersetzt, z. B. `ä -> ae`, `ö -> oe`, `ü -> ue`, `ß -> ss`
- Langtexte pro Sprache pflegen
- Attribute pro Artikel mit `TecDoc Kriterien ID`, Format-Hinweis und Wert pflegen
  - ab v0.1.58 mit Eingabepruefung: Schluesselwert-Kriterien nur mit Werten aus ihrer Schluesselliste (Herkunft TecDoc/TOPMOTIVE, gespeichert wird das Kuerzel, Liste per `Schluesselliste zuordnen...`), je Wert hoechstens 20 Zeichen, kein Bereich `30 bis 30`, `9202`/`9213`/`9220` je Artikel nur einmal
- Attribute automatisch finden und fuellen (hybrid: Regeln + Claude-KI)
  - erkennt `Label: Wert`-Zeilen und technische Daten (inkl. Bereichen und `LxBxH`-Abmessungen)
  - optional liest eine Claude-KI zusaetzlich Fliesstext und PDF-Dokumente aus
  - sichere, gegen die Stammdaten validierte Treffer werden automatisch uebernommen; unsichere landen im Bestaetigungsdialog
- Suchwoerter pro Artikel pflegen
  - werden beim Export als Referenz vom Typ `Gebrauchsnummer` (TecDoc ID `2`) in die `Gebrauchsnummern.xlsx` geschrieben, eine Zeile pro Suchwort
- OE-Nummern als freie Referenzen pro Artikel pflegen
- Vergleichsnummern mit Mitbewerber-ID pro Artikel pflegen
- Mitbewerber aus `KHer.csv` nachschlagen und direkt in Vergleichsnummern uebernehmen
- Fahrzeugverknuepfungen pro Artikel ueber Motorcodes pflegen
- Stueckliste (Lieferumfang mit Menge) und Zubehoerliste (optionales Zubehoer) pro Artikel pflegen wie in IMS, Reiter `Artikelliste(n)`
- Gefuehrter Modus (Wizard): fuehrt Schritt fuer Schritt durch alle Eingaben bis zum Export
- Tabs nach Befuellung gruppiert: erst die automatisch befuellten (Kunzer-Abruf, Praefix ⚙), dann die manuell zu pflegenden (Praefix ✎)
  - ueber einen oder mehrere Motorcodes werden die passenden KTyp-Nummern (TopMotive und TecDoc) automatisch aus den KTyp-Stammdaten (`KTyp.xlsx`) ergaenzt
  - waehrend der Eingabe werden Motorcode-Vorschlaege inklusive `meintest du`-Naehe angezeigt
  - der Fahrzeugtyp ist per Dropdown waehlbar (Standard `PKW = 2`)
- Bilder, Dokumente, Videos und Web Links erfassen
  - mit Bild-Thumbnail und PDF-Vorschau in den Bilder- und Dokumente-Tabs
  - vorhandene Zeilen koennen direkt im Formular nachbearbeitet und aktualisiert werden
  - Aenderungen werden direkt in die Output-Excel-Dateien geschrieben
- Kurzbezeichnungen und Texte per DeepL aus dem deutschen Feld in `EN`, `CZ`, `FR`, `IT` und `NL` uebersetzen
- GenArt manuell ueber die Suche auswaehlen
  - mit direkter Suche ueber das GenArt-Feld oder den Button `Suchen...`
- Produktdaten direkt von `kunzer.de` laden
  - per Artikelnummer
  - inklusive Titel, Web-Link, Bildern und Dokumenten
  - optional mit automatischer DeepL-Uebersetzung
  - mit Hintergrundladen, damit die GUI waehrenddessen fluessiger bleibt
- Eine Produktliste als CSV oder XLSX importieren und mehrere Produkte in Serie ueber Kunzer anlegen
  - mit Auswahl der zu scrapenden Daten
  - mit automatischer DeepL-Uebersetzung fuer Texte
  - mit direktem Schreiben in den festen Output-Pfad
- Exportdateien wahlweise in einen Zeitstempel-Unterordner oder direkt in einen festen Importpfad schreiben
- Vorhandene Artikel aus den Output-Dateien in einem Artikelverzeichnis erneut aufrufen
- Apollo-Importstand je Ausgabeordner: seit dem letzten Apollo-Import geaenderte Artikel werden im Verzeichnis markiert und koennen als Loeschliste (`757` / Artikelnummer, plus Blatt `Aenderungen`) gespeichert werden
- `Pruefung vor dem Import...` (ab v0.1.58): prueft alle Output-Dateien auf das, was Apollo ablehnt oder anders speichert (Klartext statt Kuerzel, Freitextfeld mehrfach, ueber 20/35/300 Zeichen, doppelte Medien, Fahrzeuge an GenArten ohne Fahrzeuge ...), mit Ergebnisfenster und Excel-Bericht
- Reiter `Uebersicht`: alle Artikel wie in Excel auf einen Blick, je Reiter Anzahl und Datum der letzten Aenderung, sortierbar, durchsuchbar (Suchfeld oben und ab v0.1.57 ein Suchfeld je Spalte), als Excel speicherbar; Zellen-Logik wie in Excel (aktive Zelle mit blauem Rahmen, Pfeiltasten, `Strg+C`/`Strg+V`): GenArten eines Artikels kopieren und auf markierte Artikel uebertragen (Ergaenzen/Ersetzen), Marke (Attribut 8988) direkt in der Zelle waehlen oder tippen - sofort fuer alle markierten Zeilen, ohne Dialog, mit `Strg+Z` (Attribute und Suchwoerter)
- Bild-, PDF- und Web-Vorschauen werden zwischengespeichert, damit wiederholtes Oeffnen spuerbar schneller ist
- Die GUI merkt sich beim Beenden ihren letzten Zustand, inklusive Pfaden, Optionen, aktuellem Artikel, Texten, Medien und geoeffnetem Tab
- Ueber `Nach Updates suchen` kann die App auf GitHub nach einem neueren Release schauen und in der gebauten EXE die neue Version direkt herunterladen und starten
- Die Projektansicht passt sich auf kleineren Displays automatisch an; grosse Bereiche und Vorschauen koennen eingeklappt werden

## Kunzer Import

Die GUI kann Produktdaten direkt von `https://www.kunzer.de` laden. Dabei nutzt sie die oeffentliche Produkt-Sitemap und rendert die Produktseite in einem Headless-Browser, damit auch clientseitig geladene Inhalte erfasst werden.

Aktuell werden automatisch befuellt:

- `Artikelnummer`
- `Kurzbezeichnung` auf Deutsch
- `Text` auf Deutsch (Artikelbeschreibung, sonst Artikelinformationen der Shopseite; hat der Shop keinen Text, bleibt der Text leer - ein vorhandener Text bleibt stehen, im Massenimport gilt `Text` dann als nicht abgerufen, es entsteht keine Textzeile und keine Text-ID; ebenso bekommt ein neuer Artikel ohne Text keine leere Textzeile, auch wenn nur `Kurzbezeichnung` angehakt ist)
- `Bilder` als direkte URL von `kunzer.de`
- `Dokumente` als direkte URL von `kunzer.de`
- `Web Link`
- produktbezogene Video-Links, falls auf der Produktseite vorhanden

Bild- und Dokumentdaten aus Kunzer werden bewusst als URL in der GUI und im Export hinterlegt.
Bei Dokumenten wird die `Art` automatisch aus der Bezeichnung bzw. dem Dateinamen abgeleitet, zum Beispiel:

- `Bedienungsanleitung` -> `14`
- `Produktinfo` -> `17`
- `Zubehoer` -> `17`

Video-Links werden automatisch auf ein einbettbares YouTube-Format im Stil `https://www.youtube.com/embed/...` normalisiert. Das gilt fuer gescrapte Kunzer-Videos und auch fuer manuell eingetragene `embed`-, `watch`-, `shorts`- oder `youtu.be`-Links.

Wenn `DEEPL_API_KEY` gesetzt ist oder der Key in der GUI eingetragen wurde, koennen die geladenen deutschen Texte direkt weiter uebersetzt werden.

Die GenArt wird nach dem Laden bewusst nicht automatisch gesetzt, sondern manuell ueber das GenArt-Suchfeld oder den Button `Suchen...` ausgewaehlt.

Abrufergebnisse von kunzer.de werden innerhalb einer Programmsitzung zwischengespeichert (spart den zweiten Seitenaufruf, z. B. fuer die Attribut-Findung). Ein erneutes `Artikel anlegen` fuer denselben Artikel holt ab v0.1.45 trotzdem immer den aktuellen Shop-Stand (vorher kam bis zum Neustart das alte Ergebnis zurueck - ein im Shop nachtraeglich ergaenztes Bild wurde so nicht gefunden), und jeder Massenimport startet mit leerem Zwischenspeicher.

## Artikelverzeichnis

Die bisherige reine Text-Vorschau wurde durch ein `Artikelverzeichnis` ersetzt. Dort werden nur Artikel aus den aktuellen Output-Dateien tabellarisch gelistet.

- Suchfeld ueber der Tabelle: mehrere Begriffe mit Leerzeichen trennen, alle muessen vorkommen (Artikelnummer, Kurz-/Text-ID, GenArt, Kurzbezeichnungen aller Sprachen, deutscher Text, OE-/Vergleichsnummern samt Hersteller, Suchwoerter); Treffer-Zaehler, `Enter` waehlt einen eindeutigen Treffer, `Esc` oder `Leeren` setzt zurueck
- Artikel koennen per Button oder Doppelklick wieder in die Maske geladen werden; der Wechsel blockiert die Oberflaeche nicht mehr (Bild-, PDF- und Video-Vorschauen laden im Hintergrund, die Liste wird nur bei geaenderten Dateien neu aufgebaut)
- fuer jeden Artikel werden Quelle, IDs und Medienanzahlen angezeigt
- Spalte `Geaendert seit Import` (ab v0.1.52): Zeitpunkt der letzten Aenderung, wenn der Artikel seit dem Apollo-Importstand bearbeitet wurde; solche Zeilen sind hellorange hinterlegt (siehe `Apollo-Importstand und Loeschliste`). Die Markierung wird nach jedem Live-Speichern, Massenimport und `Apollo-Import erledigt` nachgezogen
- ueber der Tabelle steht die Zeile `Letzter Apollo-Import: ... - seitdem n Artikel geaendert, m geloescht` (gezaehlt wie die Loeschliste seit Apollo-Import) mit den Buttons `Apollo-Import erledigt`, `Importstand setzen...` und `Loeschliste seit Apollo-Import`
- rechts werden alle aktuell in den Export-Excel-Dateien vorhandenen Daten des markierten Artikels angezeigt
- Bilder zeigen ein Thumbnail, Dokumente bei PDFs die erste Seite und sonst eine kompakte Dateivorschau
- Web Links zeigen Host-Badge und Seitentitel; der Webseiten-Screenshot (Playwright) wird nur noch auf Knopfdruck `Webseiten-Vorschau laden` erzeugt und dann zwischengespeichert

## Apollo-Importstand und Loeschliste

Apollo (IMS) kann vorhandene Artikel beim Import nicht aktualisieren: Artikel, die seit dem letzten Apollo-Import in der GUI geaendert wurden, muessen vor dem naechsten Import ueber eine Loeschliste aus Apollo entfernt werden. Ab v0.1.52 merkt sich die GUI dafuer einen Importstand.

- Der Importstand liegt als `Apollo-Importstand.json` im Ausgabeordner (`last_import_at`, `set_at`, `set_by`, `note`, `changed_since`, `delete_list_at`, `delete_list_base`, `delete_list_size`, `delete_list_count`, `delete_list_checked_at`; `deleted_since` aus einem Vorabstand wird nur noch gelesen und bei `Apollo-Import erledigt` mit dem neuen Stand als Zeitpunkt ins Journal uebernommen) und gilt damit fuer alle Instanzen, die denselben Ordner nutzen. `changed_since` ist das Aenderungsjournal (Artikel -> Zeitpunkt der letzten Aenderung, siehe unten); es wird auch gefuehrt, solange noch kein Stand gesetzt ist - die Datei hat dann ein leeres `last_import_at`. Eine fehlende oder nur das Journal enthaltende Datei bedeutet `noch kein Importstand gesetzt` - dann wird nichts markiert. Ein UTF-8-BOM (Datei von Hand gespeichert) ist erlaubt. Ist die Datei nicht lesbar (kaputt, gesperrt), zeigt die Zeile `Apollo-Importstand nicht lesbar: <Fehler>` (bei kurzer Sperre bleibt der zuletzt gelesene Stand mit Markierung stehen, mit Hinweis); `Loeschliste seit Apollo-Import` und `Apollo-Import erledigt` lesen dann erneut und melden den Fehler, statt `noch kein Importstand gesetzt` - eine nicht lesbare Datei wird nie ueberschrieben.
- Massgeblich ist die Spalte `Zuletzt geschrieben am` der Output-Dateien: je Artikel und Bereich (Kurzbezeichnung, Text, GenArt, Attribute, Suchwoerter, OE-/Vergleichsnummern, Fahrzeuge, Listen, Bilder, Dokumente, Videos, Web Links) zaehlt der juengste Zeilen-Zeitstempel. Liegt er nach dem Importstand, gilt der Artikel als `geaendert`; sind alle Zeilen juenger als der Stand, als `neu`. Beim Live-Speichern bekommen die geaenderten Bereiche den Schreibzeitpunkt sofort im Verzeichnis, ohne die Dateien neu zu lesen.
- Unveraenderte Zeilen behalten ihren Zeitstempel - beim Live-Speichern, im Massenimport und beim Export in den festen Pfad. Ein Speichern ohne inhaltliche Aenderung (Fokus- oder Artikelwechsel, Massenimport mit unveraendertem Shop-Stand, Bild-Link, der wieder dieselbe lokale Datei ergibt, `Medien neu herunterladen` mit unveraendertem Dateiinhalt) markiert deshalb nichts und schreibt auch die `Apollo-Importstand.json` nicht. Ob ein Bereich der Maske geaendert ist, wird gegen das verglichen, was die Maske beim Laden (bzw. letzten Speichern) gezeigt hat - solange der Artikel in der Maske ist, auch wenn der Verzeichnis-Eintrag danach neu eingelesen wird, weil ein Katalog erst spaeter fertig geladen ist (z. B. KTyp-Stammdaten beim ersten Start nach einer Aenderung der `KTyp.xlsx`) oder eine zweite Instanz den Artikel geaendert hat. Laden, Feld- oder Reiterwechsel, Artikelwechsel und Speichern ohne Eingabe schreiben nichts; erst eine echte Eingabe schreibt den Bereich (dann mit dem Modell der GUI, bei Fahrzeugen z. B. je Fahrzeug und verknuepfter GenArt eine Zeile mit der TecDoc-Nummer). Hat eine zweite Instanz den geladenen Artikel geaendert, zeigt die Maske bis zum erneuten Laden weiter den alten Stand: eine Eingabe im selben Bereich ueberschreibt die Fremdaenderung dort, die anderen Bereiche bleiben unberuehrt. Hat ein vorhandener Artikel keine Text- bzw. Kurzbezeichnungs-Zeile und in diesem Bereich auch keinen Text, wird beim Speichern keine leere Zeile mit neu erzeugter Modul-ID mehr angelegt (ausser der Bereich ist zuvor beim Speichern gescheitert - dann wird er immer nachgeholt).
- `Apollo-Import erledigt`: nach dem Import in Apollo klicken (mit Rueckfrage). Der neue Stand ist der Zeitpunkt der ERSTEN `Loeschliste seit Apollo-Import`, die seit dem bisherigen Stand gegen ihn oder einen frueheren Stand gespeichert wurde (`delete_list_at` mit `delete_list_base` <= Stand < `delete_list_at`) - sonst jetzt; die Rueckfrage nennt den Zeitpunkt mit Sekunden, die Artikelzahl der Liste und den Grund. Gab es seit dem Stand nur die Pruefung `Eine Loeschliste ist nicht noetig` (keine Datei), gilt deren Zeitpunkt (die Rueckfrage sagt das). Folgte auf eine solche Pruefung (nach dem Stand) noch eine echte Liste, weiss nur der Nutzer, was in Apollo ging: `erledigt` fragt dann ausdruecklich `Wurde die Loeschliste vom <Zeitpunkt mit Sekunden> (<n> Artikel) in Apollo importiert?` (Warnsymbol, Vorauswahl `Nein`). `Ja` = Stand auf die Liste; `Nein` = der Apollo-Import lief schon nach der Pruefung (ohne Liste), Stand auf die Pruefung - die Artikel der Liste bleiben markiert und kommen noch einmal auf die naechste Liste (sicher); die Liste bleibt dabei vermerkt: das naechste `Apollo-Import erledigt` nimmt wieder ihren Zeitpunkt (sicher - was danach geaendert wurde, bleibt markiert); `Abbrechen` aendert nichts (z. B. wenn der Apollo-Import noch gar nicht gelaufen ist). Die Ueberschrift dieser Rueckfrage ist die Frage selbst (`Wurde die Loeschliste vom ... in Apollo importiert?`). Ohne diese Frage gaelte bei einer nur zum Ansehen gespeicherten Liste alles, was zwischen dem Apollo-Import und der Liste geaendert wurde, still als importiert. Eine Pruefung, die nicht nach dem Stand liegt, loest die Frage nicht aus. Wurden seit dem Stand mehrere echte Listen gespeichert (`delete_list_count`, z. B. eine zweite nur zum Ansehen oder aus einer anderen Instanz), zaehlt die erste; die Rueckfrage sagt das - wurde in Apollo eine spaetere Liste importiert, danach `Importstand setzen...` auf deren Zeitpunkt stellen (sonst stehen die Artikel dazwischen nur noch einmal auf der naechsten Liste, doppelt loeschen und neu importieren schadet nicht). Wurde der Stand nach dem Speichern der Liste mit `Importstand setzen...` auf einen FRUEHEREN Zeitpunkt gestellt als den, gegen den die Liste erstellt wurde (`delete_list_base`), fehlen ihr die Artikel dazwischen: dann gilt jetzt, und die Rueckfrage warnt (Vorauswahl `Nein`), die Liste neu zu erstellen (unterscheiden sich beide Zeitpunkte nur in den Sekunden, zeigt sie sie mit Sekunden). Das Journal bleibt vollstaendig erhalten: Eintraege bis zum neuen Stand zaehlen nur nicht mehr - ein spaeter mit `Importstand setzen...` frueher gesetzter Stand (z. B. nach einem versehentlichen `erledigt`) erfasst sie wieder, auch Loeschungen und komplett geleerte Bereiche. Juengere Eintraege bleiben markiert: was nach dem Speichern der Loeschliste geaendert wurde (z. B. waehrend TecAlliance importiert, auch in einer anderen Instanz oder waehrend der Rueckfrage), stand auf keiner Liste und bleibt markiert bis zur naechsten. Offene Live-Auftraege werden vorher geschrieben, ebenso noch nicht vermerkte Artikel frueherer Massenimporte (scheitert das wieder, werden sie spaeter mit einem Zeitpunkt nach dem neuen Stand vermerkt und bleiben markiert).
- `Importstand setzen...`: Datum und Uhrzeit frei eintragen (`TT.MM.JJJJ HH:MM`, Sekunden optional `HH:MM:SS`, vorbelegt mit jetzt, optional eine Notiz), z. B. wenn der Import schon gestern lief. Das Journal bleibt erhalten und zaehlt mit allen Eintraegen nach dem neuen Stand - auch mit Aenderungen und Loeschungen aus der Zeit, bevor ueberhaupt ein Stand gesetzt war (erste Nutzung: Stand nachtraeglich auf den echten letzten Import setzen) oder bevor ein frueheres `erledigt` den Stand weitergesetzt hat. Der Vermerk der Loeschliste bleibt stehen; ob er zum neuen Stand passt, pruefen `erledigt` und die naechste Liste nach derselben Regel (`delete_list_base` <= Stand < `delete_list_at`) - passt er nicht mehr, ersetzt ihn die naechste Liste. Nur der Zeitpunkt einer Pruefung ohne Liste (`delete_list_checked_at`) entfaellt, wenn der neue Stand nicht davor liegt (die Pruefung ist damit erledigt, `erledigt` fragt nicht mehr nach ihr). Die Statuszeile zeigt den Stand mit Sekunden, wenn sie eingegeben wurden.
- Waehrend eines Massenimports, einer IMS-Uebernahme oder eines anderen Hintergrundvorgangs sind die drei Buttons gesperrt bzw. melden nur `Es laeuft bereits ein Hintergrundvorgang` - ein Stand mitten im Lauf liesse die bis dahin geschriebenen Artikel dauerhaft als importiert gelten.
- `Loeschliste seit Apollo-Import`: speichert alle seit dem Stand geaenderten, neuen und geloeschten Artikel als XLSX (oder CSV). Blatt `Loeschliste` hat den Aufbau der Apollo-Loeschlisten (Spalte A = `757`, Spalte B = Artikelnummer), Blatt `Aenderungen` zeigt je Artikel `letzte Aenderung`, `geaenderte Bereiche` und `Status` (`geaendert`, `neu`, `geloescht`). Der Zeitpunkt der Liste (nach dem Schreiben aller offenen Live-Auftraege, vor dem Einlesen) wird als `delete_list_at` im Importstand vermerkt, dazu der Stand, gegen den sie erstellt wurde (`delete_list_base`), und ihre Artikelzahl (`delete_list_size`); Bestaetigung und Statuszeile nennen ihn mit Sekunden (`Loeschliste vom 29.10.2026 08:54:50 ...`), so laesst er sich bei Bedarf mit `Importstand setzen...` eintragen. Gibt es seit dem Stand keine Aenderung, kommt nur der Hinweis `Eine Loeschliste ist nicht noetig (geprueft am ...)`; diese Pruefung wird mit `delete_list_size` 0 vermerkt, zaehlt aber nicht als Liste: die erste echte Liste danach ersetzt sie (der Zeitpunkt der Pruefung bleibt als `delete_list_checked_at` fuer die Rueckfrage in `erledigt`), weitere Pruefungen aendern nichts. Eine weitere echte Liste, solange der Vermerk zum Stand passt, aendert ihn nicht, sie zaehlt nur `delete_list_count` hoch (Pruefungen ohne Liste zaehlen nicht). Vermerke ohne `delete_list_size` (aus einem Entwicklungsstand) gelten als echte Liste. Laesst sich der Zeitpunkt nicht vermerken, warnt eine Meldung und nennt, was `erledigt` dann nimmt (eine frueher vermerkte Liste seit dem Stand, eine Pruefung ohne Liste - dann bleiben die Artikel der neuen Liste markiert - oder die Klickzeit). Laufen noch Live-Auftraege, wird keine Liste erstellt. Im Massenimport vorgemerkte Artikel, deren Vermerk im Journal gescheitert war (z. B. ein dort geleerter Bereich, der nur im Journal steht), werden vorher vermerkt; scheitert das erneut, wird keine (unvollstaendige) Liste erstellt, die Meldung nennt die Artikel. Die bisherige `Apollo-Loeschliste speichern` im Massenimport (nur der letzte Lauf) bleibt erhalten.
- Im Verzeichnis geloeschte Artikel (`Zeilen loeschen`) stehen in keiner Output-Datei mehr; sie werden mit dem Loeschzeitpunkt im Journal vermerkt und landen so trotzdem auf der Loeschliste (Status `geloescht`) - auch wenn derselbe Artikel spaeter neu angelegt wird, bis zum naechsten `Apollo-Import erledigt`. Scheitert das Loeschen mittendrin (z. B. `Bilder.xlsx` in Excel geoeffnet), werden die markierten Artikel trotzdem vermerkt - ein Teil ihrer Zeilen ist dann schon entfernt.
- Aenderungsjournal (`changed_since`): Jeder Schreibvorgang mit echter Aenderung vermerkt den Artikel mit dem Zeitpunkt seiner LETZTEN Aenderung (ein spaeterer Vermerk ersetzt einen frueheren) - Live-Speichern, Export in den festen Pfad (auch `Exportieren & Fertigstellen` im gefuehrten Modus; Export in einen Zeitstempel-Unterordner nicht), Massenimport (jeder Artikel mit geaendertem Bereich, auch wenn der Artikel spaeter im Lauf scheitert oder der Lauf abgebrochen wird; geaenderte Bereiche aus einem gescheiterten 1. Versuch zaehlen mit, ebenso nur umsortierte Attribute einer Attribut-Vorlage; vermerkt wird gesammelt waehrend des Laufs alle 30 Sekunden bzw. 25 Artikel, am Laufende und beim Schliessen des Programms mitten im Lauf - auch waehrend auf den KI-Batch gewartet wird -, jeweils mit dem Zeitpunkt des Vermerks; scheitert der Vermerk, bleiben die Artikel vorgemerkt und werden beim naechsten Vermerk nachgeholt - auch erst im naechsten Lauf, vor `Loeschliste seit Apollo-Import` bzw. `Apollo-Import erledigt` oder beim Schliessen - und immer im Ausgabeordner ihres Laufs, nie in dem eines spaeteren Laufs in einen anderen Ordner), Suchwort-Import (nur Artikel, deren Suchwoerter sich wirklich aendern) und Loeschen im Verzeichnis. Die IMS-Uebernahme vermerkt nichts (ihre Zeilen sind der Stand, den Apollo schon hat). Das Journal ist noetig, weil die Zeilen-Zeitstempel nicht jeden Fall abbilden: wird ein Bereich komplett geleert oder ein Artikel geloescht, bleibt in den Dateien kein juengerer Zeitstempel. Markierung, Zaehler und Loeschliste beruecksichtigen das Journal - auch nach einem Neuladen von der Platte oder einem Neustart. Das Journal wird nicht gekuerzt (ein Eintrag je Artikel mit dem juengsten Zeitpunkt); Eintraege bis zum Stand zaehlen einfach nicht.
- Entfernte oder umsortierte Zeilen: Aendern sich die Zeilen eines Bereichs, ohne dass eine neue Zeile dazukommt (z. B. ein Attribut, eine OE-Nummer, ein Bild oder ein Suchwort entfernt, Bilder bzw. Dokumente nur in anderer Reihenfolge), bekommen alle Zeilen des Artikels in diesem Bereich den Schreibzeitpunkt. Laedt `Medien neu herunterladen` (Massenimport) unter derselben URL eine Datei mit anderem Inhalt, wird sie unter demselben Pfad ersetzt und der Bereich gilt ebenfalls als geaendert (Zeilen gestempelt, Journal) - auch wenn danach im selben Versuch etwas scheitert (der 2. Versuch findet gleiche Bytes vor und stempelt die Zeilen trotzdem; scheitert der Artikel ganz, steht er im Journal); bei gleichem Inhalt bleibt die Datei unberuehrt. Nativ gespeicherte Dateien (JPG, PNG, GIF, PDF) werden Byte fuer Byte verglichen - so zaehlt auch eine nur geaenderte EXIF-Ausrichtung, ein anderes ICC-Profil, eine andere Transparenz oder ein geaenderter spaeterer GIF-Frame. Nur nach PNG umgewandelte Bilder (webp/tif/bmp) gelten bei anderen Bytes, aber gleichen Bilddaten (jeder Frame mit Groesse, Modus, Palette, Transparenz und Pixeln, dazu das ICC-Profil) als gleich - die Umwandlung kann mit einer anderen Pillow-Version andere Bytes ergeben. Die Zeitstempel der `Kurzbezeichnung_zu_ID.xlsx` zaehlen zum Bereich Kurzbezeichnung.
- Zeilen ohne `Zuletzt geschrieben am` (z. B. von Hand in Excel eingefuegt) zaehlen in allen Output-Dateien mit der Aenderungszeit der Datei - wie beim Schreiben, wo diese Zeit dann auch in die Zelle uebernommen wird.
- Grenzen: Nach einer IMS-Uebernahme (`IMS-Export uebernehmen...`) tragen die ergaenzten Zeilen das Uebernahmedatum - danach den Importstand neu setzen, sonst stehen diese Artikel auf der naechsten Loeschliste. Wegen des Rueckfalls auf die Aenderungszeit der Datei gelten Zeilen ohne Zeitstempel als geaendert, sobald die Datei nach dem Stand gespeichert wurde (auch von Hand in Excel). Das Journal wird von mehreren Instanzen ohne Sperre geschrieben; schreiben zwei Instanzen im selben Moment, kann ein Vermerk verloren gehen. Zeitstempel haben Sekundenaufloesung: was eine andere Instanz in derselben Sekunde schreibt, in der die Loeschliste erstellt wird, kann nach `erledigt` als importiert gelten. Als erste Liste zaehlt die zuerst im Importstand vermerkte: der Vermerk folgt erst nach dem Speichern-Dialog, speichert eine andere Instanz in dieser Zeit eine Liste, gilt deren (spaeterer) Zeitpunkt. Ein im Massenimport vorgemerkter Artikel, dessen Vermerk auch beim Schliessen des Programms noch scheitert, geht verloren (die Meldung vom Laufende nennt ihn). Ist die `Apollo-Importstand.json` kurz gesperrt oder nicht lesbar (z. B. liest eine zweite Instanz sie gerade, ein Virenscanner prueft sie oder das Netzlaufwerk setzt aus), werden Lesen und Schreiben einige Male wiederholt; scheitert ein Vermerk trotzdem, erscheint eine Meldung mit den Artikeln, die dann von Hand auf die Apollo-Loeschliste muessen (je Artikel einmal, bis ein Vermerk wieder gelingt oder `erledigt`/`Importstand setzen` folgt; Loeschungen immer), und die Statuszeile behaelt den Hinweis `Importstand nicht vermerkt`. `erledigt`, `Importstand setzen` und `Loeschliste seit Apollo-Import` aendern eine nicht lesbare Datei nicht (Meldung `konnte nicht gelesen werden`).

### Loeschlisten je Haken (ab v0.1.56)

Apollo kann unter `Artikelinformationen loeschen` einzelne Bereiche eines Artikels loeschen. `Loeschlisten je Haken...` (neben `Loeschliste seit Apollo-Import`) nutzt das: dieselben Artikel wie die Loeschliste, aber je Haken eine eigene Liste - geloescht und neu importiert wird nur, was sich geaendert hat. Hat sich bei einem Artikel z. B. nur ein Attribut geaendert, bleiben Texte, Bilder, Fahrzeuge, Referenzen (samt EAN) und das Zubehoer-Kennzeichen in Apollo unangetastet. Eine Marke aendert mit `Marke auch als Suchwort` (Standard) auch die Suchwoerter - dann steht der Artikel zusaetzlich auf `Referenzen`.

- Zuordnung der GUI-Bereiche zu den Haken (vom User in Apollo geprueft): `Art.-Detail` = Kurzbezeichnung (Zusatzbezeichnung; `Kurzbezeichnung-NEU.xlsx`, `Kurzbezeichnung_zu_ID.xlsx`), `Texte` = Langtext (Infotext; `Text-NEU.xlsx`), `Attribute` (`Attribute.xlsx`), `Referenzen` = OE-, Vergleichs- und Gebrauchsnummern/Suchwoerter (immer alle drei Dateien), `Produktgruppen` = GenArten (`GenArt_Artikel.xlsx`, zieht `Verknuepfungen` mit), `Verknuepfungen` = Fahrzeuge (`Fahrzeugverknuepfungen.xlsx`), `Medienanhaenge` = Bilder, Dokumente, Videos, Web Links (alle vier Dateien).
- Braucht einen IMS-Export (Stand in Apollo, nach dem letzten Apollo-Import erstellt): nur damit lassen sich Bereiche erkennen, die in der GUI ganz geleert wurden (z. B. alle OE-Nummern oder alle Dokumente entfernt) - sie haben keine Zeile und damit keinen Zeitstempel mehr, und das Journal kennt nur den Artikel. Verglichen wird je GUI-Bereich (Zuordnung wie `IMS-Export uebernehmen`; 232: DocType 02 = Dokument, alle uebrigen Dateitypen = Bild, auch 07 = GIF): hat Apollo zu einem Bereich Daten, die GUI aber keine Zeile mehr, kommt sein Haken dazu - auch wenn ein anderer Bereich desselben Hakens noch Zeilen hat. OE- und Vergleichsnummern stehen in Apollo zusammen in 203, Videos und Web Links zusammen als Links (232, DocType 04): sie werden je Nummer (Hersteller + Nummer ohne Leerzeichen und Gross-/Kleinschreibung) bzw. je Link verglichen - unabhaengig vom Mitbewerber-Katalog (`KHer.csv`) und davon, ob ein Link als Video oder Web Link gilt. Umgekehrt kommt der Haken auch dazu, wenn die GUI zu einem Bereich Daten hat, Apollo aber keine (z. B. Zeilen, die ein frueherer Import abgewiesen hat). Eine Text- oder Kurzbezeichnungs-Zeile ohne Text zaehlt in der GUI als vorhanden, nicht als geleert. Ohne Export bleibt die Loeschliste ganzer Artikel.
- Rueckfrage vor dem Erstellen (Warnsymbol, Vorgabe `Nein`), wenn der Abgleich nicht sicher erkennt, was Apollo noch hat: der Export ist aelter als der letzte Apollo-Import (nach `Apollo-Import erledigt` zaehlt der Zeitpunkt des Klicks - importiert wurde zwischen Liste und Klick; `erledigt` vermerkt ihn als `import_done_at` im Importstand, `Importstand setzen...` entfernt ihn wieder und uebernimmt die Notiz `Apollo-Import erledigt` nicht mehr in das Eingabefeld -, bei einem von Hand gesetzten Stand der Stand selbst; stammt der Export aus derselben Minute, nennt die Frage die Uhrzeit mit Sekunden, denn der Ordnername kennt keine); sein Ordnername nennt keinen Zeitpunkt (Format `JJJJMMTT_HHMM...`); seit dem Stand wurde schon eine Loeschliste erstellt und der Export ist aelter als sie (wurde sie eingespielt, ohne `erledigt` zu klicken, fehlt das im Export - erst `erledigt`, dann neu exportieren; wurde sie nur neu erstellt, z. B. wegen Text-Luecken, passt der Export); Artikel, die schon vor dem Stand in der GUI standen, fehlen im Export (Anzahl und Nummern; ist der Export vollstaendig?); oder ihm fehlen Tabellen, zu denen die GUI Daten hat (232, 400, 203, 207, 210, 206, 211, 222/205 - z. B. beim Export abgewaehlt). Der Ordnerdialog fuer den Export oeffnet im Ordner ueber dem zuletzt gewaehlten Export.
- Ganz geloescht (`01_Komplett_loeschen.xlsx`, wie bisher) werden: in der GUI geloeschte Artikel; Artikel, die im Export fehlen - neu angelegte kennt Apollo noch nicht (das Loeschen laeuft fuer sie ins Leere, wie bei der Loeschliste ganzer Artikel), schon vor dem Stand vorhandene bekommen einen eigenen Grund (Export unvollstaendig? Apollo hat sie dann womoeglich doch); beide werden komplett importiert, so kann ein veralteter oder unvollstaendiger Export keinen Artikel am Loeschen vorbeischleusen; neue Artikel, die Apollo schon kennt; Aenderungen ohne erkennbaren Bereich (nur im Journal); Stueckliste/Zubehoer geaendert, geleert oder nur auf einer Seite vorhanden (dafuer gibt es keinen Haken). Hat Apollo Alt-Suchwoerter als Kriterium 9595, gehen `Attribute` und `Referenzen` immer zusammen: `Attribute` loescht die 9595-Kriterien, die Suchwoerter kommen ueber die Gebrauchsnummern der `Referenzen` zurueck.
- Seit dem Stand unveraenderte Artikel: was die GUI hat und Apollo laut Export nicht (z. B. Zeilen, die nie in Apollo ankamen - beim ersten Lauf 30 Artikel vom 23.10.2026 ohne Attribute, Suchwoerter, Texte bzw. Stueckliste in Apollo), kommt wie bei geaenderten Artikeln auf den passenden Haken (Grund `seit dem Stand unveraendert - ...`, Status `unveraendert` im Blatt `Artikel`, auch auf `Loeschliste_komplett`); fehlt ein solcher Artikel im Export ganz, kommt er auf `01_Komplett_loeschen` (und in die Rueckfrage zu fehlenden Artikeln). Der Import ganzer Dateien haette beides mitgenommen. Hat Apollo dagegen mehr als die GUI, ist das nur ein Hinweis (Blatt `Artikel`, Status `unveraendert`, `nur Hinweis`) - womoeglich direkt in Apollo gepflegt, deshalb loeschen die Listen es nicht; wird derselbe Haken fuer das Nachholen ohnehin geloescht (oder der Artikel ganz), steht eine Warnung in `00_Ablauf.xlsx` und in der Abschlussmeldung (`geht verloren (nur in Apollo)`). Steht ein unveraenderter Artikel nach dem naechsten Import wieder auf den Listen, nimmt IMS seine Zeilen nicht an (IMS-Protokoll pruefen). Auch ohne Aenderung seit dem Stand gleicht der Button mit dem Export ab; `nicht noetig` meldet er erst, wenn auch das nichts ergibt (vermerkt wie bei der Loeschliste als Pruefung ohne Liste). Der Vermerk `delete_list_size` zaehlt alle Artikel der Listen.
- Hinweise in `00_Ablauf.xlsx` (Blatt `Ablauf` und Spalte `Hinweis` im Blatt `Artikel`): Angaben, die nur Apollo fuehrt und die das Loeschen vermutlich entfernt - EAN bei `Referenzen` oder `Art.-Detail` (welcher Haken sie loescht, ist ungeprueft), Zubehoer-Kennzeichen bei `Art.-Detail`, weitere Infotexte bei `Texte`, alles bei ganz geloeschten Artikeln (nicht bei in der GUI geloeschten; bei Artikeln, die im Export fehlen, kennt der Abgleich solche Angaben nicht); nach dem Import in Apollo pruefen. Ausserdem Artikel, deren Kurzbezeichnung bzw. Langtext in der GUI leer ist, waehrend Apollo einen Text hat, und die mit diesem Haken bzw. ganz geloescht werden: in der GUI nachtragen und die Loeschlisten danach neu erstellen (das Paket enthaelt noch den leeren Text). Die Abschlussmeldung nennt diese Artikel.
- Ergebnis ist ein Ordner `Apollo-Import_<Datum>_<Uhrzeit>` mit `00_Ablauf.xlsx` (Schritte: welche Liste mit welchem Haken, wie viele Artikel, welche Dateien danach; Hinweise; Blatt `Artikel` mit Haken, Grund und Hinweis je Artikel; Blatt `Loeschliste_komplett` mit allen Artikeln wie bisher - nur zusammen mit dem vollstaendigen Import der Output-Dateien verwenden, nie mit dem Ordner `Import`), den Listen `01_Komplett_loeschen.xlsx` bis `08_Medienanhaenge.xlsx` (nur die mit Artikeln; Aufbau wie VLoesch.xlsx: A = `757`, B = Artikelnummer) und dem Unterordner `Import`: je Output-Datei nur die Zeilen der Artikel und Bereiche, die vorher geloescht werden (gleiche Dateinamen, Blaetter und Spalten wie im Ausgabeordner; Medienpfade sind absolut).
- Ablauf: jede Liste mit genau ihrem Haken in Apollo einspielen (ein Artikel kann auf mehreren Listen stehen), danach in IMS die Dateien aus `Import` importieren und zum Schluss `Apollo-Import erledigt` klicken. Der Zeitpunkt wird wie bei der Loeschliste vermerkt - `erledigt` setzt den Stand darauf.
- Nach einer IMS-Uebernahme den Importstand neu setzen (siehe Grenzen): sonst zaehlen die Uebernahme-Zeitstempel als Aenderung, und z. B. die Kurzbezeichnung stuende bei fast allen Artikeln auf der Liste.

## Eingabepruefung und Pruefung vor dem Import (ab v0.1.58)

Der Abgleich Apollo <-> GUI vom 12.11.2026 hat gezeigt, was Apollo (IMS) still ablehnt oder anders speichert, als es in der GUI steht: Klartext statt Kuerzel bei Schluesselwert-Kriterien (z. B. `doppelseitig`, `12 V`, `Ja`, `FKM`), Kuerzel aus der falschen Liste (`9084` Material mit einem Kuerzel der TecDoc-Liste `Material` - Apollo zeigte `Nappaleder`), eine zweite und dritte Zeile `9202 Zusatzinfo` (Apollo haelt je Artikel nur die erste), ein Bereich `30 bis 30`, Attributwerte ueber 20 Zeichen, Suchwoerter ueber 35 Zeichen, Web-Links ueber 300 Zeichen und dieselbe Datei zweimal bei einem Artikel. Ab v0.1.58 nimmt die GUI solche Eingaben nicht mehr an, und `Pruefung vor dem Import...` findet die vorhandenen Zeilen dieser Art in den Output-Dateien.

Grundsatz: Neue und geaenderte Eingaben werden abgewiesen (mit Meldung, die den Grund und den Ausweg nennt). Vorhandene Zeilen werden nie still geaendert, gekuerzt, verschoben oder entfernt - weder beim Laden noch beim Speichern noch durch die Pruefung oder die Vorlage - und sie sperren das Speichern nicht (sonst waeren die betroffenen Artikel nicht mehr speicherbar, auch `Marke` in der Uebersicht nicht). Sie werden in der Maske markiert und in der Pruefung gemeldet; korrigiert wird von Hand. Die bisherige harte Formatpruefung (keine Zahl, `Wert` groesser als `Wert bis`, laenger als die Katalog-Laenge) bleibt, wie sie ist.

### Eingabe im Reiter Attribute

- Die Kriterienauswahl zeigt Nummer, Bezeichnung und Herkunft (`9084 | Material | TOPMOTIVE`), damit gleichnamige Kriterien unterscheidbar sind - ebenso `Zuweisen` im Bestaetigungsdialog. Fuer Kriterien des Katalogs gelten bei neuen Zeilen Format und `Max. Laenge` des Katalogs (die Felder bleiben beschreibbar).
- Schluesselwert-Kriterien nehmen nur Werte aus ihrer Liste an: im Feld `Wert` tippen, die Auswahl zeigt `Kuerzel | Bezeichnung`, gespeichert und exportiert wird das Kuerzel. Die Hinweiszeile nennt die Liste (`Schluesselliste: TecDoc/Akkuspannung (20 Werte, Stand der Datei: 02.06.2026) ...`). Eine getippte Bezeichnung wird aufgeloest (`doppelseitig` -> `DS | doppelseitig`, `Kupfer` -> `8 | Kupfer`), sonst das Kuerzel (`DS`, `46`, `194`). Es gibt keine Teiltreffer mehr. `Wert bis` ist bei Schluesselwert gesperrt (eine gefuellte Bestandszeile bleibt offen, damit man es leeren kann), die Knoepfe `Ja`/`Nein` sind nur beim Format Flag aktiv.
- Nicht still uebernommen, sondern mit Meldung abgewiesen: Text, der weder Bezeichnung noch Kuerzel der Liste ist (Klartext - `12 V`, `Ja` bei `4374`); doppeldeutiger Text (Bezeichnung eines Eintrags und zugleich Kuerzel eines anderen, z. B. `12` bei `3465`: `2 | 12` oder Kuerzel `12` = 7,2) - dann den gemeinten Eintrag in der Auswahl anklicken; `Kuerzel | Bezeichnung`, bei dem beides nicht zusammenpasst. In der Auswahl steht dann nichts vorausgewaehlt, `Enter` uebernimmt nichts still.
- Listen mit Zahlen als Bezeichnungen (z. B. Akkuspannung, Akkukapazitaet, Netzspannung, Anzahl Teile, Antriebs-Vierkant): eine getippte Zahl ist ein Wert, nie still ein Kuerzel - `12` trifft auch `12,0`, `3,7` wird `8 | 3,7`, `1000` bei `3217` wird `M | 1000`; ein getipptes `8` bei `3465` wird abgewiesen (nur Kuerzel von `8 | 3,7`), wer diesen Eintrag meint, klickt ihn an. In Wortlisten (Material, Batterie, seitig ...) bleibt das Tippen des Kuerzels moeglich. Kuerzel sind immer Text: `01` ist nicht `1`, Buchstaben-Kuerzel (`DS`, `M`, `A2`) und fuehrende Nullen bleiben, wie sie sind.
- Kuerzel, das die Katalogdatei nicht kennt: `Schluesselwerte.xlsx` (Stand 02.06.2026) enthaelt nur aktive Eintraege - was fehlt, ist in IMS gesperrt (z. B. Material `147`) oder neuer als der Export (Material `309`-`314`, Ergaenzungsartikel `993`, `994`). Ist ein solcher Wert der Form nach ein Kuerzel (z. B. `310` bei Material), fragt die Maske nach (`... steht nicht in der Schluesselliste ... (Stand der Datei: ...) ... Als Kuerzel '310' uebernehmen?`, Vorgabe `Nein`); `Ja` uebernimmt ihn ungeprueft, die Zeile ist orange markiert und steht in der Pruefung unter `Pruefen`.
- Kriterium ohne gueltige Liste: kein Wert uebernehmbar, die Meldung verweist auf `Schluesselliste zuordnen...`.
- Weitere Regeln fuer alle Attribute: `Wert` und `Wert bis` je hoechstens 20 Zeichen (Apollo speichert nicht mehr; bei Schluesselwerten zaehlt das Kuerzel - eine lange Bezeichnung wie `HDPE (Hart-Polyethylen)` ist erlaubt); `Wert` gleich `Wert bis` (`30 bis 30`) wird abgewiesen - bitte nur `Wert` fuellen. Die Freitextfelder `9202` Zusatzinfo, `9213` Zusatz LI/SI 2 und `9220` Information haben je Artikel hoechstens eine Zeile (Apollo uebernimmt nur die erste): ist das Feld belegt, bietet die Maske das naechste freie Freitextfeld an (`Den Text stattdessen in 9213 | Zusatz LI/SI 2 eintragen?`), sonst meldet sie `Alle Freitextfelder (9202, 9213, 9220) sind belegt.` Andere Kriterien duerfen mehrfach vorkommen (z. B. `200`, `436`, `727` kommen so in Apollo an).
- Vorhandene Zeilen, die gegen eine Regel verstossen, bleiben stehen und werden markiert: rote Schrift = Fehler, orange = pruefen; die Hinweiszeile der markierten Zeile nennt den Grund (`Bestandszeile: ...`, bei einer ueberzaehligen Freitextzeile mit dem naechsten freien Feld). `Auswahl aktualisieren` ohne Aenderung loest nie eine Warnung aus; eine ueberzaehlige Freitextzeile laesst sich darueber in ein freies Feld verschieben. Eine Bestandszeile mit Klartext wird als Klartext angezeigt (nicht mehr still als `DS | doppelseitig`) und unveraendert exportiert; der Export einer Schluesselwert-Zeile schreibt immer den Text vor dem ersten `|`, sonst den Text selbst - beim Schreiben wird nichts mehr aufgeloest.
- Sind Attributkatalog bzw. Schluesselwerte nicht geladen (Laufwerk G: nicht erreichbar), wird nichts geprueft und nichts umgeschrieben: roter Hinweis ueber der Eingabe, Hinweis in der Statuszeile, und vor jeder neuen oder geaenderten Schluesselwert-Zeile (bzw. jedem der Maske unbekannten Kriterium) die Rueckfrage, ob der Wert ungeprueft uebernommen werden soll. Abhilfe: Projekt > `Datenstaemme` > `Neu laden`. Die Regeln fuer Laenge, `von gleich bis` und Freitextfelder gelten weiter.

### Attribut-Findung, Bestaetigungsdialog, Vorlage

- Alle Eingaberegeln gelten auch fuer Regel-Stufe, KI, Internet-Recherche, Label-Mining und Massenimport: ein Treffer, der gegen eine Regel verstoesst, wird nie sicher uebernommen, sondern landet mit dem Grund im Bestaetigungsdialog bzw. in der `Attribute_Pruefliste.xlsx`. Die Textfindung nimmt ein nacktes Kuerzel nie automatisch - eine Zahl im Produkttext ist ein Wert: `Akkuspannung: 12 V` wird nicht mehr als Kuerzel `12` (= 7,2) gespeichert, sondern kommt als `2 | 12` mit dem Hinweis `doppeldeutig ... bitte pruefen` in den Dialog; `Akkukapazitaet: 8 Ah` bleibt unsicher (`nur als Kuerzel gefunden (8 | 2,4)`). Ein KI-Bereich mit `von` groesser `bis` (`10 - 8`) wird nicht mehr still zum Einzelwert `10`.
- Bestaetigungsdialog: ein nicht aufloesbarer Schluesselwert laesst sich nicht anhaken (Meldung); `Zuweisen` folgt den Regeln der Maske; `Uebernehmen` weist z. B. eine zweite `9202` derselben Uebernahme ab und nennt alle abgewiesenen Zeilen in einer Meldung (`Nicht uebernommen: ...`). Ohne geladene Kataloge lassen sich Schluesselwert-Zeilen nicht anhaken.
- Vorlage (Attribute nach Referenzartikel, `davon 1:1 uebernehmen`): verstossen die Zeilen einer Kopier-ID schon im Referenzartikel gegen eine Regel (z. B. mehrere `9202`-Zeilen, Klartext-Schluesselwert, ueber 20 Zeichen, `von gleich bis`), wird diese ID im Lauf weder kopiert noch gesucht noch ersetzt - die vorhandenen Zeilen der Zielartikel bleiben, wie sie sind (wie bei einer Kopier-ID ohne Zeile im Referenzartikel). Statuszeile bzw. Startmeldung nennen das (`1:1 nicht uebernommen - Referenzartikel verstoesst gegen eine Eingaberegel: 9202`), vor einem Massenimport mit Rueckfrage `Lauf trotzdem starten?`. Ist der Referenzartikel bereinigt (z. B. ueberzaehlige Zusatzinfos nach `9213`/`9220` verschoben), ersetzt der naechste Lauf die Zeilen der Zielartikel wieder wie bisher.
- Ein beim Update noch offener KI-Batch einer Vorversion wird beim Abholen mit den neuen Regeln ausgewertet; seine sicheren Schluesselwert-Treffer gehen sicherheitshalber in die Pruefliste (`vor dem Update gefunden - bitte pruefen`).

### Suchwoerter, Links, Medien

- Suchwoerter: hoechstens 35 Zeichen (Apollo schneidet laengere ab oder lehnt sie ab; bis v0.1.57 galten 50) - bei der Eingabe, beim Datei-Import und fuer automatisch erzeugte Kandidaten (Regel und KI; Kandidaten mit 36-50 Zeichen entfallen). Vorhandene laengere Suchwoerter bleiben in Maske und Datei, bis sie geaendert werden; im Reiter stehen sie in roter Schrift, der Zaehler sagt `davon n laenger als 35 Zeichen (Apollo schneidet ab oder lehnt ab)`.
- Web Links und Videos: hoechstens 300 Zeichen bei der Eingabe (Apollo speichert nur die ersten 300 - der Link waere tot), derselbe Link nicht zweimal beim Artikel (Vergleich ohne Leerraum und `/` am Ende, Schema und Host ohne Gross-/Kleinschreibung). Eine unveraenderte Zeile wird nicht geprueft (blosses Anklicken meldet nichts). Vorhandene lange Links bleiben, sind rot markiert, und unter der Tabelle steht `1 Link laenger als 300 Zeichen - Apollo schneidet ihn ab.` bzw. `n Links laenger als 300 Zeichen - Apollo schneidet sie ab.` Der Abgleich mit dem IMS-Export (`Loeschlisten je Haken...`) vergleicht nur die ersten 300 Zeichen - lange Links gelten dort nicht mehr dauerhaft als Abweichung.
- Bilder und Dokumente: dieselbe Datei bzw. derselbe Link mit gleicher Art und gleicher Sprache nicht zweimal beim Artikel (Vergleich ohne Gross-/Kleinschreibung, `\` = `/`; dieselbe Datei in zwei Sprachen oder Arten bleibt erlaubt). `Dateien waehlen` ueberspringt schon vorhandene Dateien mit einer Meldung; der Kunzer-Abruf liefert jeden Link nur noch einmal (vorher entstand so z. B. bei `800BEW11L` dieselbe Datei zweimal).

### Pruefung vor dem Import

- Knopf `Pruefung vor dem Import...` im Artikelverzeichnis in der Zeile des Apollo-Importstands (nach `Loeschlisten je Haken...`); vor dem Apollo-Import klicken. Die Pruefung liest die Rohzeilen aller 14 Output-Dateien des Ausgabeordners (nach dem Schreiben offener Live-Auftraege) und prueft sie mit denselben Regeln wie die Maske. Sie schreibt nichts in den Ausgabeordner und aendert keine Zeile. Waehrend Massenimport, IMS-Uebernahme oder einem anderen Hintergrundvorgang ist der Knopf gesperrt. Ohne geladene Kataloge fragt sie, ob sie ohne Schluesselwert-Pruefung laufen soll (`Trotzdem pruefen (alle uebrigen Regeln)?`, Vermerk `Schluesselwert-Zeilen nicht geprueft (n Zeilen)` im Ergebnis). Werden gerade noch Aenderungen gespeichert, prueft sie nicht (`... die Pruefung saehe einen halben Stand. Bitte kurz warten und erneut versuchen.`).
- Drei Stufen: `Fehler` = IMS lehnt ab oder Apollo speichert etwas anderes (sicher), `Pruefen` = ohne Blick in IMS nicht entscheidbar (Katalogstand, fehlende Liste, Listenwechsel), `Hinweis` = wirkungslos oder doppelt, kein Schaden.
- Regeln: Attribute - `Schluesselwert: Klartext statt Kuerzel` (Fehler; die Datei muss das Kuerzel selbst enthalten, auch `Kuerzel | Bezeichnung` in der Zelle ist ein Fehler), `Schluesselwert: Wert bis gefuellt` (Fehler), `Attribut: Wert ueber 20 Zeichen` (Fehler), `Attribut: von gleich bis` (Fehler), `Attribut: Freitextfeld mehrfach` (Fehler; die erste Zeile bleibt ohne Befund), `Attribut: Format` (Fehler, die bisherige Pruefung), `Schluesselwert: Listenwechsel nicht bestaetigt` (Pruefen), `Schluesselwert: Kuerzel nicht in der Schluesselliste` (Pruefen, mit Stand der Katalogdatei), `Schluesselwert: keine Schluesselliste` (Pruefen), `Attribut: Kriterium nicht im Katalog` (Pruefen), `Attribut: Format weicht vom Katalog ab` (Pruefen), `Attribut: Bereich mit negativem Wert bis` (Hinweis); Gebrauchsnummern - `Suchwort ueber 35 Zeichen` (Fehler); Web Link und Videos - `Link ueber 300 Zeichen` (Fehler), `Link doppelt` (Hinweis); Bilder und Dokumente - `Mediendatei doppelt` (Hinweis), auf Wunsch `Mediendatei inhaltsgleich` (Hinweis, gleiche Groesse und gleicher SHA-1 unter anderem Namen) und `Mediendatei fehlt` (Fehler); Fahrzeugverknuepfungen - `Fahrzeugzeile fuer GenArt ohne Fahrzeuge` (Hinweis, je Artikel und GenArt ein Befund mit Zeilenzahl; GenArten aus dem Blatt `GenArt ohne Fahrzeuge`, Vorgabe `17692`, `4563`). Die Fahrzeugzeilen fuer diese GenArten werden in v0.1.58 weiter geschrieben, nur gemeldet. Alt-Suchwortzeilen (`9595`) werden uebersprungen. Laesst sich eine Zeile nicht auswerten, steht sie als `Zeile nicht pruefbar` (Pruefen) im Ergebnis - die Pruefung bricht nie ab.
- Vorschlaege, wo sie sicher sind: das Kuerzel zum Klartext, wenn die Textfindung eindeutig aufloest (`DS | doppelseitig`, `8 | 3,7`), sonst nichts (kein Raten); `nach 9213 verschieben` fuer eine ueberzaehlige Freitextzeile, solange ein Feld frei ist; `Wert bis leeren` bzw. `Wert bis leeren oder Zeile entfernen`; `zweite Zeile entfernen` bei Doppeln.
- `Schluesselwert: Listenwechsel nicht bestaetigt`: Hat ein Kriterium eine neue Liste bekommen (Zuordnungsdatei bzw. Programm-Vorgabe mit `Bisherige Tabelle`, heute `9084` Material: TOPMOTIVE/`Stg_Material`, vorher TecDoc/`Material`) und ist `Bestand geprueft am` leer, meldet die Pruefung jede Zeile des Kriteriums, deren Kuerzel in beiden Listen Verschiedenes bedeutet - mit beiden Lesarten und dem Schreibdatum (`Kuerzel 194 bedeutet in der gueltigen Liste ... 'Nappaleder'; bis zum Listenwechsel zeigte die Maske dafuer 'HDPE (Hart-Polyethylen)' ...`) und dem Vorschlag `falls '<alte Bezeichnung>' gemeint war: <Kuerzel> | <alte Bezeichnung>`. Sind alle Zeilen geprueft bzw. korrigiert, im Ergebnisfenster `Listenwechsel als geprueft vermerken...` klicken (Rueckfrage je Kriterium): der Vermerk kommt in die Zuordnungsdatei (fuer die Programm-Vorgabe `9084` entsteht dabei eine Dateizeile mit denselben Listen) und gilt fuer alle Arbeitsplaetze; danach prueft die App erneut und meldet diesen Wechsel nicht mehr. Laesst sich die Datei nicht schreiben oder hat ein anderer Arbeitsplatz inzwischen zugeordnet, gibt es eine Meldung und keinen Vermerk. Erst vermerken, wenn kein Arbeitsplatz mehr mit v0.1.57 arbeitet (v0.1.57 bietet fuer `9084` weiter die alte Liste an).
- Ergebnisfenster (nicht modal; ein neues ersetzt ein offenes): Kopf mit Ausgabeordner, Zeitpunkt und Katalogstand (`Schluesselwerte vom 02.06.2026, Attributkatalog vom 02.06.2026`), Uebersicht je Regel (Stufe, Befunde, Zeilen), Filter `Stufe` und `Regel`, Tabelle `Stufe | Regel | Datei | Zeile | Artikel | Feld | Wert | Grund | Vorschlag` (Spaltenkoepfe sortieren, `Zeile` = Excel-Zeile in der Datei; gebuendelte Fahrzeugbefunde zeigen die erste Zeile und die Zahl der Zeilen, z. B. `286 (140 Zeilen)`). Doppelklick laedt den Artikel in die Maske. Knoepfe `Als Excel speichern...`, `Mediendateien vergleichen...` (Inhaltsvergleich und fehlende Dateien, auf G: rund 10-15 s, einmal je Pruefung; liest die Dateien nur), `Listenwechsel als geprueft vermerken...`, `Erneut pruefen`, `Schliessen`. Die Statuszeile fasst zusammen: `Pruefung vor dem Import: n Fehler, m zu pruefen, k Hinweise (z Zeilen betroffen).`
- Excel-Bericht `Pruefung-vor-Import_<JJJJ-MM-TT>_<HHMM>.xlsx`, Vorgabeordner ist der Sicherungsordner (`G:\Apollo\GUI-Sicherungen`; fehlt er, der Ordner darueber). Blaetter: `Zusammenfassung` (je Regel Stufe, Befunde, Zeilen und was Apollo damit macht; Hinweise; Grundlage mit Ausgabeordner, Zeitpunkt, Programmversion, Attributkatalog und Schluesselwerte mit Pfad und Dateidatum, Zuordnungsdatei, GenArten ohne Fahrzeuge, gepruefte Zeilen je Datei), `Befunde` (Stufe, Regel, Datei, Excel-Zeile, Artikelnummer, Feld, Wert, Grund, Vorschlag, Zeilen), `Schluessellisten` (je benutztem Schluesselwert-Kriterium: Herkunft, Liste, Quelle - Programm-Vorgabe, Zuordnungsdatei, gleicher Name oder keine -, Werte, Zeilen, Listenwechsel offen; so lassen sich die Listen einmal gegen IMS halten) und `Regeln` (alle Regeln mit Erklaerung und den drei Stufen). Der Bericht darf nicht im Ausgabeordner liegen (eine dort in Excel geoeffnete Datei blockiert `IMS-Export uebernehmen`, und die Sicherung naehme ihn jedes Mal mit) - die App lehnt das ab.
- Grenzen: Ob ein Kuerzel, das die Katalogdatei nicht kennt, in IMS gesperrt oder nur neuer ist, kann die GUI nicht unterscheiden - deshalb `Pruefen` statt `Fehler`; ein frischer Export von `Schluesselwerte.xlsx` und `Attribute alle.xlsx` aus IMS behebt das. Die Pruefung laeuft nur auf Knopfdruck (nicht automatisch vor den Loeschlisten) und korrigiert nichts.

## Uebersicht

Der Reiter `Uebersicht` (direkt hinter `Projekt`, ab v0.1.52) zeigt alle Artikel des Ausgabeordners wie in Excel auf einen Blick - eine Zeile je Artikel, dazu je Reiter, was gepflegt ist.

- Spalten: Artikelnummer, Kurzbezeichnung (DE, gekuerzt), Marke (Attribut 8988), GenArten (IDs), Letzte Aenderung, Seit Import (`ja`, wenn seit dem Apollo-Importstand geaendert), danach je Bereich `Anzahl (TT.MM.)` = Zeilen in der Output-Datei und Datum der letzten Aenderung (Kurzbezeichnung und Text als `Text-Modul-ID · n Spr. (TT.MM.)`), `-` wenn leer
- Suchfeld wie im Artikelverzeichnis (alle Begriffe muessen vorkommen; zusaetzlich zaehlen die Zellen der Zeile, also auch Marke und Datum), Treffer-Zaehler `n Artikel (m geaendert seit Import)`, mit Suche `n von N Artikeln (m geaendert seit Import)`
- Spaltensuche (ab v0.1.57): ueber jedem Spaltenkopf steht ein Suchfeld, das nur in dieser Spalte sucht. Wie im Suchfeld oben muessen alle Begriffe vorkommen (Gross-/Kleinschreibung egal; `ue` findet auch `ü` und umgekehrt - die Kurzbezeichnungen stehen mit `ue`, die GenArt-Bezeichnungen mit `ü` in den Dateien). `-` zeigt leere Zellen (z. B. Artikel ohne Marke, ohne GenArt, ohne Bilder), `=Text` nur genaue Treffer (`=100` nur den Artikel 100, `=93` nur die GenArt 93, `=3` genau 3 Zeilen). Durchsucht wird der Zelltext; bei `GenArten` zaehlen auch die Bezeichnungen, bei `Seit Import` `ja` bzw. `nein`. Mehrere Spaltenfelder und das Suchfeld oben gelten zusammen; der Zaehler zeigt dann `n von N Artikeln (m geaendert seit Import) - Spaltensuche: Marke, GenArten`. `Enter` filtert sofort neu (auch nach einer Marken- oder GenArt-Aenderung, deren Zeilen sonst stehen bleiben, bis neu gefiltert wird), Pfeil unten geht in die Tabelle (Zelle derselben Spalte), `Esc` leert das Feld, `Tab` geht ins naechste Feld, `Strg+F` in der Tabelle springt ins Suchfeld der aktiven Spalte. `Leeren` leert das Suchfeld oben und alle Spaltenfelder, `Esc` im Suchfeld oben nur dieses. Die Suchzeile folgt dem waagerechten Rollen, der Spaltenbreite und der Fenstergroesse. Die Spaltensuche wird nicht mit dem Sitzungszustand gespeichert; `Als Excel speichern...` schreibt die gefilterten Zeilen.
- Klick auf einen Spaltenkopf sortiert, ein zweiter Klick dreht die Richtung um (Anzahlen und Daten werden als Zahl bzw. Datum sortiert, nicht als Text)
- Doppelklick laedt den Artikel wie aus dem Verzeichnis in die Maske; geaenderte Artikel sind wie im Verzeichnis hellorange hinterlegt
- Mehrfachauswahl (ab v0.1.53): mit `Strg`/`Umschalt` + Klick mehrere Zeilen markieren, ab v0.1.55 auch mit `Umschalt` + Pfeil oben/unten (Bereich ab der aktiven Zelle) und `Strg+A` (alle sichtbaren Zeilen, z. B. nach einer Suche); rechts unter der Suche steht `n markiert`. Die markierten Zeilen sind die Ziele fuer `GenArten einfuegen...` und die Marke (nur wenn nichts markiert ist, die aktive Zeile); der Doppelklick laedt weiter die angeklickte Zeile (in der Spalte `Marke`: Marke bearbeiten)
- `Als Excel speichern...` schreibt die Tabelle (aktuelle Suche, Spaltensuche und Sortierung) als `Uebersicht_<Datum>.xlsx`, Blatt `Uebersicht`
- Die Zeilen werden je Artikel nur neu gebaut, wenn sich sein Eintrag oder der Importstand geaendert hat; gezeichnet wird nur, solange der Reiter sichtbar ist

### Zellen-Logik: aktive Zelle, Tastatur, Strg+C / Strg+V, Kontextmenue (ab v0.1.54, aktive Zelle ab v0.1.55)

Die Uebersicht arbeitet wie Excel mit einer **aktiven Zelle** = Fokuszeile x aktive Spalte. Sie hat einen blauen Rahmen (2 px, Kunzer-Blau `#3567A8`), der mitwandert: beim Klick, mit den Pfeiltasten, beim Rollen (Mausrad, Rollbalken), Sortieren, Suchen, Neuzeichnen, beim Ziehen einer Spaltenbreite, bei Groessenaenderung und Reiterwechsel; ist die Zeile aus dem Bild gerollt oder die Tabelle leer, ist kein Rahmen zu sehen. Die aktive Spalte ist zusaetzlich im Spaltenkopf mit `▸` markiert (der Sortierpfeil bleibt daneben), und eine Hinweiszeile unter der Tabelle sagt, was `Strg+C`/`Strg+V` dort tun (steht die Schreibmarke in einem Suchfeld der Spaltensuche, zeigt sie stattdessen den Suchhinweis dieser Spalte). Klicks auf einen Spaltenkopf sortieren nur und aendern die aktive Spalte nicht. Nach dem Start ist `GenArten` aktiv - `Strg+C`/`Strg+V` verhalten sich damit wie in v0.1.53, bis eine andere Spalte angeklickt wird.

- Maus: ein Klick (links, rechts oder doppelt) auf eine Zelle markiert die Zeile wie bisher und macht die Zelle zur aktiven Zelle. `Umschalt` + Klick erweitert nur die Markierung (die aktive Zelle bleibt als Anker stehen). `Strg` + Klick schaltet die Zeile um: kommt sie dazu, wird sie die aktive Zelle; wird die aktive Zeile selbst abgewaehlt, geht die aktive Zelle wie in Excel auf die naechstgelegene noch markierte Zeile (bei gleichem Abstand die darunter); wird eine andere Zeile abgewaehlt, bleibt die aktive Zelle (und mit ihr der Anker fuer `Umschalt` + Klick) stehen - die aktive Zelle liegt so immer in der Markierung, die Statuszeile sagt `<Artikel> abgewaehlt - n markiert, aktive Zelle <Artikel>`. Ist danach nichts mehr markiert, bleibt die angeklickte Zeile aktiv (`nichts markiert`). Tasten und Klicks direkt nach dem `Strg` + Klick (auch vorausgetippt, waehrend die GUI noch beschaeftigt ist - z. B. `Strg+C`, `Umschalt` + Klick, ein weiterer `Strg` + Klick, `Enter` in der Auswahl der Marke) sehen schon die neue Markierung und aktive Zelle. Klicks auf den Rahmen selbst gehen an die Zelle darunter - auch Doppelklicks: landet einer der beiden Klicks auf dem 2-px-Rahmen (Tk erkennt dann keinen Doppelklick, weil der Rahmen ein eigenes Fenster ist), erkennt die GUI ihn selbst (dieselbe Zelle, binnen 500 ms und 5 px - die Grenzen von Tk in der Tabelle); auch die untersten Pixel einer Zeile, auf denen der untere Rahmen liegt, gehoeren dabei zur Zelle.
- Tastatur: Pfeil links/rechts wechselt die aktive Spalte (die Spalte wird ins Bild gerollt), `Pos1`/`Ende` springen in die erste bzw. letzte Spalte, Pfeil oben/unten wechselt die Zeile, `Umschalt` + oben/unten erweitert die Markierung, `Strg+A` markiert alle sichtbaren Zeilen, `Strg+F` springt ins Suchfeld der aktiven Spalte (Spaltensuche; aktive Zelle und Markierung bleiben). Ist die Auswahl der Marke offen, gehen alle Tasten in sie (siehe unten) - die Tabelle bewegt sich dann nicht.
- `Strg+C` kopiert den Wert der aktiven Zelle: in der Spalte `GenArten` die GenArten (wie bisher genau einer markierten Zeile), in der Spalte `Marke` die Marke (beides in die Zwischenablage der Uebersicht, die genau EINEN Inhalt haelt - eine neue Kopie ersetzt die alte, auch die der anderen Art), in jeder anderen Spalte den angezeigten Zelltext in die Windows-Zwischenablage (Statuszeile `<Spalte> von <Artikel> kopiert: <Text>`).
- `Strg+V` fuegt die Zwischenablage der Uebersicht in die aktive Spalte der markierten Zeilen ein: `GenArten` -> `GenArten einfuegen...` (Dialog wie unten), `Marke` -> sofort, ohne Dialog (siehe `Marke direkt in der Zelle`). Passt der Inhalt nicht zur Spalte, sagt die Statuszeile `Zwischenablage enthaelt GenArten - bitte eine Zelle der Spalte GenArten anklicken` (bzw. `... eine Marke ... Spalte Marke`); in anderen Spalten `In die Spalte <X> kann nichts eingefuegt werden`.
- `Strg+Z` macht die letzte Markenaenderung rueckgaengig (mehrstufig) - nur Markenaenderungen: nach `GenArten uebertragen` bleibt es stehen (siehe unten).
- Rechtsklick setzt die aktive Zelle auf die angeklickte Zelle und zeigt die passenden Befehle: Spalte `GenArten`: `GenArten kopieren`, `GenArten einfuegen...`; Spalte `Marke`: `Marke setzen...` (oeffnet die Auswahl in der Zelle), `Marke kopieren`, `Marke einfuegen`; andere Spalten: `Wert kopieren`; immer `Rueckgaengig: Marke <X> (n Artikel)` (ausgegraut, wenn `Strg+Z` dort stehen bleibt) und `Artikel laden` (wie der Doppelklick, laedt die Zeile der aktiven Zelle). GenArten wie bisher: Kopieren bei genau einer markierten Zeile, Einfuegen bei passender Kopie und mindestens einem anderen markierten Artikel als die Quelle; waehrend Massenimport, IMS-Uebernahme oder einem Hintergrundvorgang sind Einfuegen, Setzen und Rueckgaengig ausgegraut (per Tastatur: Statuszeile).

### GenArten uebertragen (ab v0.1.53)

- Kopieren: Rechtsklick auf genau einen Artikel > `GenArten kopieren` (oder `Strg+C`, solange die Spalte `GenArten` aktiv ist) merkt seine GenArten in ihrer Reihenfolge; die Statuszeile zeigt `GenArten von <Artikel> kopiert: <ID Bezeichnung>, ...`. Ein Artikel ohne GenArt kopiert nichts (eine fruehere Kopie bleibt).
- Einfuegen: die Zielartikel markieren > Rechtsklick > `GenArten einfuegen...` (oder `Strg+V` in der Spalte `GenArten`). Der kopierte Artikel selbst wird uebersprungen, auch wenn er mit markiert ist. Der Dialog zeigt Quelle (IDs + Bezeichnungen), Anzahl der Ziele und je Ziel `Artikel | bisher | danach | Fahrzeuge` (z. B. `+1 GenArt-Verknuepfung je Fahrzeug, +35 Zeilen`, `-120 Zeilen`, `5 Fahrzeuge fallen weg`; Ziele ohne Aenderung `unveraendert`) sowie die Summe der Fahrzeugzeilen. Wahl:
  - `Ergaenzen` (Vorgabe): fehlende GenArten kommen in der Reihenfolge der Quelle hinter die vorhandenen, vorhandene bleiben.
  - `Ersetzen`: die Ziele bekommen genau die GenArten der Quelle in deren Reihenfolge, andere werden entfernt. Hat ein Ziel schon genau diese GenArten (nur anders sortiert), bleibt es unveraendert - eine reine Umsortierung wuerde alle Zeilen neu stempeln und den Artikel ohne fachliche Aenderung auf die Loeschliste setzen.
- Regeln wie im Reiter GenArt der Maske (dieselben Funktionen, Ergebnis in den Dateien gleich - im Test gegen dieselben Eingaben in der Maske geprueft): eine neue GenArt wird mit allen Fahrzeugen des Artikels verknuepft, ein Artikel ohne GenArt verknuepft mit der ersten GenArt alle Fahrzeuge (keine Zeilen ohne GenArt mehr). Mit einer entfernten GenArt fallen ihre Fahrzeugzeilen weg, Fahrzeuge, die nur an entfernten GenArten haengen, fallen ganz weg; erst danach kommen beim `Ersetzen` die neuen GenArten dazu (wie in der Maske: erst entfernen, dann hinzufuegen). Fallen Fahrzeuge weg, nennt der Dialog das rot, und vor dem Schreiben kommt eine Rueckfrage mit Artikeln und Anzahl (Warnsymbol, Vorauswahl `Nein`; `Nein` schreibt nichts). Sollen die Fahrzeuge an den neuen GenArten haengen bleiben: erst `Ergaenzen` uebertragen, danach `Ersetzen` (wie der Tipp in der Maske: erst die neue GenArt hinzufuegen, dann die alte entfernen).
- Vor dem Schreiben: laufende Live-Speicherungen werden abgeschlossen und das Verzeichnis mit den Dateien abgeglichen. Zeigt die Maske ein Ziel, werden ihre offenen Eingaben zuerst gespeichert; bleibt etwas ungespeichert (z. B. OE-Zeile ohne Hersteller, gesperrte Datei), bricht die Uebertragung mit Meldung ab. Gemerkte Eingaben eines Ziels (Speichern nach dem Verlassen gescheitert) werden zuerst nachgeholt; gelingt das nicht, bricht sie ebenfalls ab. Waehrend Massenimport, IMS-Uebernahme oder einem anderen Hintergrundvorgang ist `GenArten einfuegen...` ausgegraut bzw. per `Strg+V` mit Statuszeile abgewiesen.
- Geschrieben wird nur, was sich aendert: `GenArt_Artikel.xlsx` und - wenn sich Fahrzeugzeilen aendern - `Fahrzeugverknuepfungen.xlsx`, jede Datei einmal fuer alle Ziele. Sind diese Dateien nicht frei (z. B. in Excel geoeffnet, auch auf einem anderen Rechner), wird nichts geschrieben (Meldung mit Datei). Sonst werden sie zuerst als `<Name>_Sicherung_<Zeitstempel>.xlsx` in den Sicherungsordner der IMS-Uebernahme kopiert (`G:\Apollo\GUI` -> `G:\Apollo\GUI-Sicherungen`). Unveraenderte Zeilen behalten ihr `Zuletzt geschrieben am`; unveraenderte Ziele werden weder geschrieben noch markiert. Die geaenderten Ziele kommen ins Journal des Apollo-Importstands (hellorange, Loeschliste seit Apollo-Import). Statuszeile: `GenArten auf n Artikel uebertragen (k unveraendert) - Fahrzeugzeilen: +x / -y`.
- Danach zeigen Uebersicht und Verzeichnis den neuen Stand; zeigt die Maske ein Ziel, wird sie aus den Dateien neu gefuellt. In der Uebersicht werden ab v0.1.57 wie bei der Marke nur die geaenderten Zeilen nachgezogen: Reihenfolge, Markierung, aktive Zelle und Rollposition bleiben stehen, und Zeilen, die danach nicht mehr zur Suche bzw. Spaltensuche passen (z. B. `GenArten` = `-`), bleiben sichtbar, bis neu gefiltert wird (`Enter` in einem Suchfeld, Sortieren, `Liste aktualisieren`, `Als Excel speichern...`). Laden, Artikelwechsel und Neustart schreiben danach nichts (die gemerkten Staende sind nachgezogen).
- Scheitert das Schreiben: scheitert schon `GenArt_Artikel.xlsx`, ist nichts geaendert. Scheitert `Fahrzeugverknuepfungen.xlsx`, nachdem `GenArt_Artikel.xlsx` geschrieben ist, holt die GUI `GenArt_Artikel.xlsx` aus der eben angelegten Sicherung zurueck - beide Dateien bleiben auf dem alten Stand (Meldung nennt Datei und Zielartikel); einfach die Datei schliessen und erneut einfuegen. Scheitert auch das Zurueckholen (Meldung `ACHTUNG`, nennt Datei, betroffene Artikel und Sicherung): `GenArt_Artikel_Sicherung_<Zeitstempel>.xlsx` aus dem Sicherungsordner zurueck in den Ausgabeordner kopieren (als `GenArt_Artikel.xlsx`), in der Uebersicht `Liste aktualisieren` klicken und die GenArten erneut uebertragen, sobald die Fahrzeugdatei frei ist. Die betroffenen Artikel stehen dann schon im Journal (sie kommen auf die naechste Loeschliste, das schadet nicht).

### Marke direkt in der Zelle (ab v0.1.55; v0.1.54: Marke uebertragen mit Dialogen)

Die Marke (Attribut `8988`, siehe `Marke (Attribut 8988)`) wird in der Spalte `Marke` wie in Excel direkt in der Zelle gepflegt - fuer einen Artikel oder fuer viele markierte auf einmal (z. B. 2000 Artikel `KUNZER`), ohne Vorschau- oder Eingabedialog. Geschrieben wird inhaltlich dasselbe wie bei derselben Aenderung in der Maske (Reiter `Attribute` und `Suchwoerter`); einziger Unterschied ist die Reihenfolge: eine fehlende Markenzeile bzw. das Marken-Suchwort kommt nach vorn (per `Hinzufuegen` in der Maske kaemen sie ans Ende).

- Bearbeiten: in der Spalte `Marke` tippen (das Zeichen startet die Eingabe), `F2`, `Enter`, Doppelklick oder Rechtsklick > `Marke setzen...` oeffnet ueber der aktiven Zelle eine Auswahl (editierbar) mit den Namen der Markenliste und den in den Artikeln gepflegten Marken, alphabetisch; vorbelegt ist die Marke der Zeile (beim Tippen das Zeichen). Getippter Text filtert die Liste (Anfang zuerst), passt genau eine Marke zum Anfang, wird sie wie in Excel vervollstaendigt (`k` -> `KUNZER`, der ergaenzte Rest ist markiert: weitertippen ersetzt ihn, `Entf` loescht ihn) - vervollstaendigt wird nur eine Marke, die mit dem Getippten beginnt, und zwar nach jeder Taste (nicht erst beim Loslassen); `Pfeil unten` klappt die Liste auf. Die Auswahl bekommt den Tastaturfokus sofort: auch vorausgetippte Zeichen (z. B. `kunzer` + `Enter`, waehrend die GUI noch eine Aenderung schreibt, auch direkt nach einem `Strg` + Klick) landen alle in ihr - eine Taste, die trotzdem in der Tabelle ankommt, geht in die offene Auswahl (Zeichen, Ruecktaste, `Entf`, Pfeil links/rechts, `Enter` setzt den Text, der in der Auswahl steht, `Escape`/`Tab` verwerfen), nie oeffnet sie eine neue. Die Statuszeile sagt, fuer wie viele Zeilen die Marke gilt (`Marke waehlen oder tippen - 4 markiert: Enter setzt sie auf alle 4 markierten Zeilen, Escape bricht ab.`; ohne Markierung `nichts markiert: Enter setzt sie auf die aktive Zeile <Artikel>`).
- `Enter` oder ein Klick auf einen Eintrag der Liste setzt die Marke **sofort auf alle markierten Zeilen**; nur wenn nichts markiert ist, auf die aktive Zeile - nie auf eine nicht markierte Zeile, solange etwas markiert ist (dieselbe Regel fuer `Marke setzen...` und `Strg+V`; liegt die aktive Zelle ausnahmsweise ausserhalb der Markierung, springt sie beim Oeffnen auf die naechste markierte Zeile, die Auswahl steht immer ueber einem Ziel). Bis zur Nachrunde von v0.1.55 machte ein `Strg` + Klick, der eine Zeile abwaehlte, genau diese Zeile zur aktiven - getippt landete die Marke dann nur auf der abgewaehlten Zeile. Fuer viele Zeilen: erst markieren (`Umschalt` + Klick, `Umschalt` + Pfeil, `Strg+A`, einzelne Zeilen mit `Strg` + Klick ausnehmen), dann tippen, `F2`/`Enter` oder Rechtsklick > `Marke setzen...` - ein Doppelklick markiert wie in Excel zuerst nur die angeklickte Zeile. `Escape`, `Tab` oder ein Klick daneben (Fokusverlust, Statuszeile `Marke nicht geaendert.`) schliesst die Auswahl ohne Aenderung - auch `Tab` bzw. `Umschalt+Tab` in der aufgeklappten Liste (ttk uebernaehme dort sonst den markierten Eintrag); nur `Enter` oder ein Klick in der Liste setzt. Eine Eingabe, die einer Marke der Markenliste entspricht (Name oder Schreibweise, `tdl`, `MotoMeter`), bekommt deren Schreibweise (`T D L`, `MOTO METER`); andere Eingaben gelten wie getippt. Leer oder laenger als erlaubt (Katalog `8988`, sonst 20 Zeichen): Hinweis in der Statuszeile, die Auswahl bleibt offen.
- Kopieren und Einfuegen: `Strg+C` in der Spalte `Marke` (oder Rechtsklick > `Marke kopieren`) merkt die Marke der aktiven Zelle (Statuszeile `Marke von <Artikel> kopiert: <Marke>`; ein Artikel ohne Marke kopiert nichts, eine fruehere Kopie bleibt; eine zu lange Marke laesst sich nicht kopieren). `Strg+V` (oder `Marke einfuegen`) setzt sie sofort auf alle markierten Zeilen (ohne Markierung: auf die aktive Zeile); ist der kopierte Artikel mit markiert, bleibt er meist `unveraendert`.
- Haekchen `Marke auch als Suchwort (alte Marke aus den Suchwoertern entfernen)` ueber der Tabelle (Vorgabe an, wird mit dem Sitzungszustand gespeichert): an = Attribut `8988` und Suchwoerter, aus = nur das Attribut (`Gebrauchsnummern.xlsx` bleibt unberuehrt - ausser bei Alt-Suchwortzeilen `9595`, siehe Regeln).
- Regeln (unveraendert seit v0.1.54): eine vorhandene `8988`-Zeile bekommt den neuen Wert an Ort und Stelle (Bezeichnung, Format, Position bleiben), fehlt sie, kommt die Marke als erste Attributzeile dazu (Marke vorn wie beim Referenzartikel); keine andere Attributzeile wird angefasst. Suchwoerter (mit Haekchen): Suchwoerter, die der bisherigen Marke oder einer ihrer Schreibweisen aus der Markenliste entsprechen (Vergleich wie bei Dubletten: `TDL` = `T D L`, Gross-/Kleinschreibung egal), fallen weg; fehlt die neue Marke (in keiner ihrer Schreibweisen), wird sie das erste Suchwort; alle anderen Suchwoerter behalten ihre Reihenfolge. Schreibweisen der NEUEN Marke werden nie entfernt: wer WEBER auf einen WEBER-Artikel mit dem Suchwort `Weber Hydraulik` setzt, aendert nichts. Ziele mit dieser Marke und passenden Suchwoertern bleiben `unveraendert` und werden weder geschrieben noch markiert (fehlt nur das Marken-Suchwort, wird es ergaenzt); ist nur die Schreibweise anders (`MotoMeter` -> `MOTO METER`), aendert sich die Attributzeile, ein vorhandenes Suchwort der Marke bleibt. Ein Artikel mit ungueltiger Attributzeile (z. B. Text in einem numerischen Attribut) kann wie in der Maske keine Attribute speichern: er zaehlt als `nicht moeglich` und bleibt unveraendert (eine zu lange eigene Markenzeile dagegen wird durch die neue Marke ersetzt). Stehen bei einem geaenderten Ziel noch Alt-Suchwortzeilen (`9595`, geschrieben bis v0.1.31) in der `Attribute.xlsx`, werden wie beim Speichern der Suchwoerter in der Maske beide Dateien im selben Schreibvorgang geschrieben: die `Attribute.xlsx` ohne die `9595`-Zeilen, die `Gebrauchsnummern.xlsx` mit allen Suchwoertern des Artikels samt den Alt-Suchwoertern - auch mit Haekchen aus und wenn die neue Marke schon unter den Alt-Suchwoertern steht (bis v0.1.54 gingen die Alt-Suchwoerter verloren, wenn sich nur die Markenzeile aenderte; die aktuellen Daten haben keine `9595`-Zeilen). Die Statuszeile nennt das (`Alt-Suchwoerter (9595) von n Artikeln in die Gebrauchsnummern uebernommen`).
- Rueckmeldung ohne Dialog, in der Statuszeile: `Marke KUNZER auf n Artikel gesetzt (k unveraendert, j nicht moeglich (ungueltige Attributzeile): <bis zu 5 Artikel>) - Suchwoerter: +a / -b - Strg+Z macht es rueckgaengig` (Haekchen aus: `Suchwoerter nicht angepasst`); ohne Aenderung `Marke <X>: keine Aenderung - ...`. Bei `nicht moeglich` stehen nur die Artikelnummern (die ungueltige Zeile steht im Reiter `Attribute` des Artikels), damit Zaehler und `Strg+Z` am Ende der Zeile sichtbar bleiben. Eine Meldung kommt nur, wenn etwas zu tun ist: Output-Datei gesperrt bzw. nicht beschreibbar (z. B. in Excel geoeffnet) oder die Maske zeigt ein Ziel mit noch nicht gespeicherten Eingaben - dann wird nichts geschrieben.
- Nach der Aenderung bleiben Reihenfolge (auch bei Sortierung nach `Marke`), Markierung, aktive Zelle und Rollposition stehen; nur die geaenderten Zeilen werden nachgezogen (Marke, Anzahl, `Seit Import`, hellorange). Die naechste Sortierung, Suche oder `Liste aktualisieren` ordnet neu.
- Ablauf und Sperren wie bei `GenArten uebertragen`: Live-Speicherungen abschliessen, Verzeichnis abgleichen, Ziel in der Maske zuerst sichern (bleibt etwas ungespeichert: Abbruch mit Meldung), gemerkte Eingaben der Ziele nachholen; die Dateien, die sich aendern (`Attribute.xlsx` bei geaenderter Markenzeile, `Gebrauchsnummern.xlsx` bei geaenderten Suchwoertern), muessen frei sein und werden je einmal fuer alle Ziele geschrieben (unveraenderte Zeilen behalten ihr `Zuletzt geschrieben am`); scheitert die zweite Datei, wird die erste auf den Stand vor dem Schreiben zurueckgeholt. Die geaenderten Ziele - genau diese - kommen ins Journal des Importstands (hellorange, Loeschliste), Uebersicht, Verzeichnis und - zeigt sie ein Ziel - die Maske werden nachgezogen; Laden, Artikelwechsel und Neustart schreiben danach nichts. Waehrend Massenimport, IMS-Uebernahme oder einem Hintergrundvorgang ist die Markenaenderung gesperrt (Statuszeile).
- **Rueckgaengig (`Strg+Z`, Rechtsklick > `Rueckgaengig: Marke <X> (n Artikel)`)**: macht die letzte Markenaenderung der Sitzung rueckgaengig, mehrstufig (bis zu 50 Schritte, je Aenderung bzw. `Strg+V` ein Schritt). Jeder betroffene Artikel bekommt seine Attributzeilen und Suchwoerter von vorher zurueck (Inhalt; geschrieben ueber denselben Weg: je Datei einmal, Journal, Maske, Uebersicht). Statuszeile `Rueckgaengig: Marke von n Artikeln wiederhergestellt - Strg+Z: auch Marke <Y> (m Artikel) rueckgaengig machen`.
  - Nur Markenaenderungen: `GenArten uebertragen` laesst sich nicht rueckgaengig machen. Kam es nach der letzten Markenaenderung, tut `Strg+Z` nichts - Statuszeile `Strg+Z macht nur Markenaenderungen rueckgaengig - die letzte Aktion (GenArten uebertragen) laesst sich nicht rueckgaengig machen.`, der Eintrag im Kontextmenue nennt den Schritt und ist ausgegraut (bis zur Nachrunde von v0.1.55 nahm ein reflexhaftes `Strg+Z` nach dem Einfuegen von GenArten still die aeltere, evtl. 2000 Artikel grosse Markenaenderung zurueck). Der Stapel bleibt: eine spaetere Markenaenderung ist wieder rueckgaengig zu machen; danach bleibt `Strg+Z` an derselben Stelle stehen (`die Aktion davor (GenArten uebertragen) ...; Marke <X> (n Artikel) und aeltere Markenaenderungen bleiben`) - wie Excel, das nach einer nicht rueckgaengig zu machenden Aktion nicht weiter zurueckgeht.
  - Uebersprungene Artikel bleiben unangetastet und werden nach Grund genannt: `seither geaendert` (z. B. in der Maske), `geloescht (nicht mehr im Ausgabeordner)` und `alter Stand nicht schreibbar (z. B. zu lange Marke)` - etwa eine von Hand zu lang gepflegte Marke, die die Aenderung repariert hatte (`... - 2 uebersprungen (1 seither geaendert: A; 1 geloescht (nicht mehr im Ausgabeordner): B)`). Kommt von einem Schritt gar nichts mehr zurueck (z. B. alle seine Artikel geloescht), faellt er vom Stapel (`Rueckgaengig uebersprungen: Marke <X> (n Artikel) - 1 geloescht ...`) und das naechste `Strg+Z` erreicht den aelteren Schritt (bis zur Nachrunde blieb der Stapel dann haengen).
  - Der Stapel gilt je Ausgabeordner und Sitzung: ein anderer Ausgabeordner oder ein Neustart leert ihn. Ist eine Datei gesperrt (oder zeigt die Maske ein Ziel mit ungespeicherten Eingaben), bleibt der Schritt auf dem Stapel und laesst sich spaeter erneut ausfuehren.
- **Sicherungen**: vor der ERSTEN Markenaenderung der Sitzung je Ausgabeordner werden die Dateien, die sich aendern, als `<Name>_Sicherung_<Zeitstempel>.xlsx` in den Sicherungsordner der IMS-Uebernahme kopiert (`G:\Apollo\GUI` -> `G:\Apollo\GUI-Sicherungen`); danach je Datei erst wieder, wenn ihre letzte Sicherung durch die Markenaenderung aelter als 30 Minuten ist (auch Strg+Z zaehlt mit). Dazwischen ersetzt `Strg+Z` die Sicherung je Aenderung - sonst laegen bei 2000 Einzelaenderungen 4000 Sicherungen im Ordner. Fuer die Rueckholung beim Scheitern der zweiten Datei haelt die GUI den Stand vor dem Schreiben im Speicher (laesst er sich nicht zurueckschreiben, legt sie ihn als Sicherung ab und nennt sie in der Meldung).
- Leistung: 2000 markierte Artikel (Echtdaten, 3.816 Artikel im Ausgabeordner) setzen dauert rund 1,2-1,7 s (Planen ~0,35-0,45 s, Schreiben ~0,2-0,25 s, Journal ~0,02 s, Anzeige ~0,4-0,5 s), `Strg+Z` darauf rund 1 s; die Dauer steht im Leistungsprotokoll (`Marke setzen (Uebersicht)`). Die Auswahl oeffnet in rund 10-20 ms (die Breite der aufklappenden Liste wird nur bei einer Aenderung neu gesetzt - jede Stil-Aenderung kostet ein Neu-Layout von rund 0,2 s).

## IMS-Export uebernehmen (TAF 2.7)

Ueber `IMS-Export uebernehmen...` im Artikelverzeichnis (ab v0.1.47) liest die App einen kompletten Apollo-IMS-Export (TAF 2.7: Exportordner mit Unterordner `0757`, `0757_PIC.zip` und `0757_DOC.zip`) und ergaenzt damit die Output-Dateien. Ziel: der Datenstamm der GUI ist danach mindestens so vollstaendig wie Apollo.

- Regel `GUI gewinnt je Artikel und Datei`: Zeilen, die in der GUI schon vorhanden sind, bleiben unveraendert; nur in der GUI fehlende Artikel bzw. Bereiche kommen aus dem Export dazu (Kurzbezeichnungen, Texte, GenArten, Attribute, Suchwoerter, OE-/Vergleichsnummern, Fahrzeugverknuepfungen, Stueck-/Zubehoerlisten, Bilder, Dokumente, Videos, Web Links). Abweichungen zwischen GUI und IMS werden nicht angefasst, sondern im Bericht aufgelistet. Einzige Aenderung an vorhandenen GUI-Zeilen: leere Text-Modul-IDs werden gefuellt (im Bericht unter Hinweise).
- Vorher werden alle Excel-Dateien des Ausgabeordners als `<Name>_Sicherung_<Zeitstempel>.xlsx` in den Sicherungsordner neben dem Ausgabeordner kopiert (`G:\Apollo\GUI` -> `G:\Apollo\GUI-Sicherungen`); dort entstehen auch der Bericht `TAF-Sync-Bericht_<Zeitstempel>.xlsx` (Uebersicht, Konflikte mit beiden Staenden, Hinweise; bei einem Abbruch der bis dahin gesammelte Teilbericht) und das Protokoll `TAF-Sync-Protokoll_<Zeitstempel>.txt`. Ist eine Output-Datei in Excel geoeffnet, startet die Uebernahme nicht.
- Benutzt werden die in den Einstellungen hinterlegten Kataloge (GenArten, Attribute, KHer, KTyp). Fehlt einer, startet die Uebernahme nicht - ohne `KHer.csv` wuerden z. B. alle Referenznummern zu OE-Nummern, und das liesse sich wegen der Regel mit einem zweiten Lauf nicht mehr reparieren.
- Medien aus den Zips werden nur fuer Artikel kopiert, die in der GUI noch keine Bilder bzw. Dokumente haben (Ablage wie beim Kunzer-Abruf unter `Medien\<Artikel>`); das Herstellerlogo landet unter `Medien\_logo` (mit `--no-media` entfaellt auch das Logo).
- Hersteller aus Tabelle 203 werden ueber `KHer.csv` (Spalte VGL) als Vergleichs- oder OE-Nummern eingeordnet; unbekannte Herstellernummern kommen als OE-Nummern mit Hinweis im Bericht. EAN (209), Status (212) und GUID (299) werden nur gezaehlt.
- Waehrend der Uebernahme laeuft die Oberflaeche weiter (Schreibsperre wie beim Massenimport); das Laden aus dem Verzeichnis ist solange gesperrt und Schliessen fragt nach. Danach werden Artikelverzeichnis und Maske aus den Dateien neu geladen; die Maske muss dafuer vorher gespeichert sein (bei nicht gespeicherten Bereichen, z. B. einer OE-Zeile ohne Hersteller, startet die Uebernahme nicht).
- Ohne Oberflaeche: `python apollo_import_gui.py --ims-sync <Exportordner> <Ausgabeordner> [--no-media]` (auch mit der EXE; die Zusammenfassung steht dann nur im Protokoll, ein Fehler in `TAF-Sync-Fehler_<Zeitstempel>.txt` im Sicherungsordner). Die Kommandozeile nimmt die Standard-Katalogpfade und hat keine Sperre gegen eine gleichzeitig laufende GUI - die GUI vorher schliessen. Das Modul `taf_sync.py` laesst sich auch direkt aufrufen (`python taf_sync.py <Exportordner> <Ausgabeordner> --report <xlsx>`), dann ohne Sicherung und Katalogpruefung.

## Leistung, Live-Speichern und Caches

- Live-Speichern laeuft in einem Hintergrund-Thread mit Warteschlange: Aenderungen in der Maske blockieren die Oberflaeche nicht mehr (Statuszeile zeigt `Speichere im Hintergrund ...` und danach `Live gespeichert: <Artikel>`). Geschrieben wird nur, was sich seit dem Laden bzw. letzten Speichern wirklich geaendert hat (Fingerabdruck je Artikel und Bereich); ein Fokusverlust ohne Aenderung schreibt nichts. Eingereihte Auftraege verwirft der Hintergrund-Schreiber nur, solange ein Massenimport die Output-Dateien besitzt (eigenes Flag, gesetzt vom Start bis zum Ende des Laufs) - nie, weil die Maske gerade gefuellt wird. Bis v0.1.52 pruefte er dafuer die Sperre, die auch jedes Laden und jeder Artikelwechsel setzt: eine Eingabe, deren Auftrag genau waehrend eines Wechsels begann (z. B. Suchwort in 77M505, sofort 77M810 getippt), ging still verloren (15 von 20 Versuchen); ebenso konnte der Folgeauftrag ausbleiben, der nach einer GenArt-Aenderung die Fahrzeugzeilen nachzieht. Trifft dieser Folgeauftrag auf einen schon wartenden Auftrag desselben Artikels, wird er mit ihm zusammengefasst und behaelt dessen juengeren Stand (bisher ersetzte er ihn durch den Stand des GenArt-Auftrags, und z. B. ein direkt danach getipptes Suchwort wurde nicht geschrieben); zwei wartende Folgeauftraege behalten den juengeren. Wurde nach dem GenArt-Auftrag schon ein Auftrag mit Fahrzeugzeilen fuer den Artikel eingereicht (er traegt die neue GenArt und die aktuellen Fahrzeuge), entfaellt der Folgeauftrag ganz (Reihenfolge der Einreichung je Auftrag): bis v0.1.52 lief er, wenn dieser Auftrag beim Abholen des GenArt-Ergebnisses schon begonnen hatte, danach und schrieb die alte Fahrzeugliste zurueck - ein gerade entferntes Fahrzeug kam wieder, auch das Schliessen reparierte das nicht. Aendert eine GenArt die Fahrzeugzeilen nicht (z. B. eine GenArt ohne Fahrzeugzeile entfernt), gibt es keinen Folgeauftrag; der Verzeichnis-Eintrag uebernimmt ab v0.1.53 trotzdem die neue GenArt-Zuordnung der Fahrzeuge (sonst lud ein Artikelwechsel die alte Zuordnung zurueck, und eine wieder hinzugefuegte GenArt blieb ohne Fahrzeuge). Entfernen und sofortiges Wiederhinzufuegen einer GenArt waehrend des Schreibens ergibt dank der Einreichungsnummern denselben Stand wie mit Pause (GenArt an allen Fahrzeugen). Holt ein Nachholer eine gemerkte GenArt-Eingabe nach, nimmt der Folgeauftrag die Fahrzeuge aus den Dateien und streicht die entfernten GenArts wie die Maske (Fahrzeuge nur an ihnen fallen weg).
- Scheitert ein Bereich (z. B. Datei in Excel geoeffnet), werden die uebrigen Bereiche trotzdem geschrieben; der gescheiterte wird beim naechsten Anlass nachgeholt (mit dem Maskenstand) und beim Beenden gibt es eine Warnung, falls noch etwas offen ist. Export, Loeschen und Massenimport warten vorher auf die Warteschlange. Ab v0.1.52 geht die Eingabe dabei auch beim Artikelwechsel nicht mehr verloren:
  - Verlassen eines Artikels mit gescheitertem Bereich (getippte Nummer, Nummer geleert, Doppelklick im Verzeichnis oder in der Uebersicht): der Nachholer wird geschrieben und (begrenzt, max. 30 s) abgewartet; scheitert er wieder, wird der Wechsel abgebrochen wie bei einem fachlichen Fehler, und die Meldung nennt die Datei (`OE-Nummern.xlsx konnte nicht geschrieben werden (z. B. in Excel geoeffnet) - bitte die Datei schliessen und erneut versuchen`). Bisher galt der eingereihte Nachholer als gesichert, scheiterte nach dem Wechsel erneut, und zurueck im Artikel schrieb der naechste Nachholer den Dateistand - die Eingabe war still weg, die Warnung beim Beenden ebenfalls.
  - Scheitert ein Auftrag erst, nachdem der Artikel verlassen wurde, merkt sich die App seine Eingabe (Bundle des juengsten gescheiterten Auftrags samt Ausgabeordner). Wird der Artikel wieder geladen (getippt, Doppelklick, Uebersicht, leere Maske + Nummer), schreibt sie diese Eingabe zuerst erneut (begrenzt gewartet): gelingt es, liest sie den Artikel aus den Dateien neu und laedt diesen Stand; scheitert es wieder, laedt sie den Dateistand und setzt die gescheiterten Bereiche aus der gemerkten Eingabe in die Maske (Statuszeile: `... noch nicht in den Dateien (<Datei> gesperrt?): Eingabe wiederhergestellt ...`). Der Marker bleibt, der naechste Speichervorgang schreibt also die Eingabe - nie den Dateistand. Ein noch nie geschriebener Artikel wird dabei aus der gemerkten Eingabe geladen statt als neu geleert.
  - Von der gemerkten Eingabe gelten nur ihre gescheiterten Bereiche: Der Nachholer uebernimmt sein (altes) Bundle nie in den Verzeichnis-Eintrag, sondern das Verzeichnis wird nach dem Schreiben neu gelesen (Zeilen-Cache: nur die geschriebenen Dateien werden neu geparst; mit dem Echtdatenstand von 3.800 Artikeln rund 1 s, nur in diesem seltenen Fall) und der gemerkte Stand des Artikels daraus abgeleitet. Was eine zweite Instanz oder der eigene Massenimport inzwischen in anderen Bereichen geaendert hat (z. B. Web-Link, Langtext, GenArt), bleibt so in Maske, Verzeichnis und Dateien. Uebernaehme der Nachholer sein Bundle (bei mehreren Bereichen den ganzen Eintrag, sonst GenArt und Modul-IDs), verschwaenden die Fremdzeilen aus der Maske, gaelten als gespeichert, und die naechste eigene Eingabe loeschte sie aus den Dateien. Zieht der Nachholer nach einer gemerkten GenArt die Fahrzeugzeilen nach, nimmt er die Fahrzeuge aus den Dateien. Laeuft der Nachholer nach der Wartezeit noch, zeigt die Maske den Dateistand und die gescheiterten Bereiche aus der gemerkten Eingabe (nicht das ganze alte Bundle). Die gescheiterten Bereiche selbst ueberschreiben eine neuere Fremdaenderung im selben Bereich (Maske gewinnt je Bereich).
  - Beim Beenden werden auch die gemerkten Eingaben verlassener Artikel noch einmal geschrieben; was weiter scheitert, nennt die bisherige Warnung (`Trotzdem beenden?`).
  - Waehrend eines Massenimports (auch beim Warten auf den KI-Batch, bis zu 2 h) wird nicht gespeichert. Wird dann ein Artikel mit ungespeicherten oder gescheiterten Bereichen verlassen (getippte Nummer, Nummer geleert, Doppelklick im Verzeichnis oder in der Uebersicht), fragt die App `Waehrend des Massenimports wird nicht gespeichert. Eingaben in <A> (<Bereiche>) verwerfen und <B> laden?` (Warnsymbol, Vorauswahl `Nein`; Bereiche, die nur gemerkt werden, nennt die Frage als `merken`, nicht als `verwerfen`). Solange ein Wechsel bzw. das Laufende des Massenimports auf das Schreiben wartet, nimmt die Maske keinen weiteren Wechsel an (Statuszeile `Bitte warten - das Speichern des bisherigen Artikels laeuft noch.`). `Nein` bleibt beim Artikel; `Ja` laedt den anderen Artikel: die Eingabe in Bereichen, deren Schreiben schon vor dem Lauf gescheitert war, wird als gemerkte Eingabe geparkt (nachgeholt bzw. wiederhergestellt beim naechsten Laden oder beim Schliessen, verworfen, wenn der Lauf den Bereich neu schreibt), alle anderen Eingaben werden wie bestaetigt verworfen (Statuszeile nennt beides). `Bitte zuerst korrigieren` waere waehrend des Laufs nicht moeglich (bis v0.1.52 lud der Doppelklick ohne Pruefung, die Eingaben waren still verloren). Der Hinweis `<Datei> konnte nicht geschrieben werden` erscheint nur, wenn beim Verlassen wirklich ein Schreibversuch erneut scheiterte - ein Marker allein (z. B. waehrend des Laufs, der nichts schreibt) sagt nichts ueber die Datei.
  - Am Ende eines Massenimports werden ungespeicherte Eingaben in der Maske zuerst geschrieben, wenn der Lauf diesen Artikel nicht neu geschrieben hat (bisher lud der Abschluss den letzten Artikel des Laufs und verwarf sie still); laesst sich eine Eingabe auch dann nicht speichern (fachlicher Fehler), bleibt die Maske bei diesem Artikel. Hat der Lauf den Artikel neu geschrieben, gewinnt wie bisher der Lauf; die Statuszeile nennt die verworfenen Eingaben.
  - Die gemerkte Eingabe entfaellt mit dem Marker: sobald die Bereiche geschrieben sind (Live-Speichern, Export in den festen Pfad), ein Massenimport die Bereiche neu geschrieben hat (nur ergaenzte Marken-Attribute zaehlen nicht), der Suchwort-Import die Suchwoerter geschrieben hat, der Artikel im Verzeichnis geloescht wird oder eine neue, leere Maske unter der Nummer angelegt wird. Gemerkt wird nur fuer den aktuellen Ausgabeordner; nach einem Wechsel des Ausgabeordners wird nichts nachgeholt oder wiederhergestellt.
- Massgeblich sind immer die Output-Dateien: Laden aus dem Artikelverzeichnis liest geaenderte Dateien vorher neu ein (ab v0.1.41), und beim Programmstart fuellt die App die Maske eines gespeicherten Artikels aus den Dateien statt aus der Sitzungsdatei (ab v0.1.43). Vorher konnte der beim letzten Schliessen gemerkte Maskenstand nach einer Aenderung von aussen (Massenimport, Bereinigung, zweite Instanz) beim naechsten Fokuswechsel zurueckgeschrieben werden. Nur ein noch nicht gespeicherter Entwurf kommt weiter aus der Sitzungsdatei.
- Artikelwechsel in der Maske (ab v0.1.48): Wird die Artikelnummer in einer gefuellten Maske auf eine andere Nummer geaendert, gilt das als Wechsel, nicht als Umbenennen. Offene Aenderungen werden noch unter der alten Nummer gespeichert; danach wird die neue Nummer aus dem Verzeichnis geladen, wenn es sie gibt, sonst die Maske fuer den neuen Artikel geleert (Statuszeile sagt, was passiert ist). Vorher wurde der komplette Maskeninhalt unter der neuen Nummer gespeichert und blieb beim folgenden `Artikel anlegen` als gepflegter Stand stehen - so bekam z. B. 800WSG01.1.6 alle Attribute von 800WSG01.1.5; eine vorhandene Nummer wurde dabei mit dem Maskeninhalt ueberschrieben. Ohne geladenen Artikel (frischer Start, leere Maske): eine vorhandene Nummer wird in die leere Maske geladen; steht ein Entwurf in der Maske, fragt die App vor dem Ueberschreiben nach (`Nein` ueberschreibt den Artikel vollstaendig mit dem Entwurf, verglichen gegen den aktuellen Dateistand - auch wenn der Artikel frueher in der Sitzung geladen und seitdem von aussen oder vom eigenen Massenimport geaendert wurde; bis v0.1.52 blieben Bereiche, die der Entwurf wie beim frueheren Laden zeigte, mit den neuen Fremdzeilen stehen); eine neue Nummer wird erst geschrieben, sobald etwas eingegeben ist (erst Daten, dann Nummer tippen bleibt moeglich). Wird die Nummer geleert, gilt der Artikel als verlassen (offene Aenderungen werden noch gesichert, die Maske geleert). Kann ein Wechsel nicht sichern (z. B. OE-Zeile ohne Hersteller, Web-Link ohne `http(s)://`, gesperrte Datei), bleibt die Maske beim alten Artikel und der naechste Klick auf `Artikel anlegen` zeigt den Grund (waehrend eines Massenimports fragt die App stattdessen, siehe oben). Dieselbe Pruefung gilt ab v0.1.52 auch fuer den Doppelklick im Artikelverzeichnis bzw. in der Uebersicht und fuer `Ausgewaehlten Artikel laden`: zeigt die Maske einen anderen Artikel, werden dessen offene Aenderungen erst gesichert; was sich nicht sichern laesst, bricht das Laden mit Meldung ab (bis dahin lud der Doppelklick ohne Pruefung, und die Eingabe war still verloren). Derselbe Artikel laesst sich weiter per Doppelklick neu laden (das zeigt den Dateistand: eine nicht speicherbare Eingabe wie ein Web-Link ohne Schema entfaellt dabei, eine wegen gesperrter Datei gescheiterte Eingabe wird wiederhergestellt). Der beim Laden gemerkte Stand (siehe `Apollo-Importstand und Loeschliste`) gilt nur, solange der Artikel in der Maske ist: fuer einen verlassenen Artikel, dessen Verzeichnis-Eintrag danach ersetzt wird, zaehlt wieder der Dateistand.
- Tab `Fahrzeuge` mit vielen Fahrzeugen (77M810: 1.849): die Maske haelt je Zeile das bereinigte Fahrzeug im Speicher, statt bei jedem Fokuswechsel die Tabellenwerte neu zu lesen und zu bereinigen; schon bereinigte Fahrzeuge werden nicht erneut bereinigt, und beim Laden eines Artikels wird die Spalte `GenArt` nicht mehr erst fuer die alten Zeilen beschriftet.
- Excel-Dateien werden immer erst als Temp-Datei geschrieben und dann eingetauscht - eine gesperrte Zieldatei bleibt vollstaendig erhalten.
- Lesen und Schreiben der Output-Dateien nutzt einen eigenen XLSX-Leser/-Schreiber (Inline-Strings, gleiches Dateiformat wie bisher) plus Zeilen-Cache im Speicher; dadurch dauert z. B. das Schreiben der `Fahrzeugverknuepfungen.xlsx` (16.000 Zeilen) rund 0,1 s statt 2 s.
- Stammdaten (KTyp, Attribute, Schluesselwerte, GenArten) und die geparsten Output-Dateien werden unter `%LOCALAPPDATA%\Apollo Import GUI\cache` zwischengespeichert; der Cache erkennt geaenderte Quelldateien und neue Programmversionen selbst. Der Ordner darf jederzeit geloescht werden (naechster Start parst dann einmal neu, KTyp ca. 10 s im Hintergrund). Mit v0.1.58 werden die Schluesselwerte beim ersten Start einmal neu aufgebaut (Dubletten zaehlen je Herkunft und Tabelle, Kuerzel bleiben Text); der Index der Schluessellisten und ihre Zuordnung werden nie zwischengespeichert.
- Schwere Pakete (Playwright, PyMuPDF, Anthropic) werden erst beim ersten Gebrauch geladen; der Start ist dadurch deutlich schneller.
- PDF-Vorschau (ein Hintergrund-Thread je Vorschau) und PDF-Text fuer die Attribut-Findung nutzen PyMuPDF, das nicht threadsicher ist: jede Verwendung (Oeffnen, Rendern bzw. Text lesen, Schliessen) laeuft unter einer gemeinsamen Sperre (`PYMUPDF_LOCK`), Download und Oberflaeche nicht. Bis v0.1.52 konnte schnelles Durchklicken von Artikeln mit PDF-Dokumenten das Programm abstuerzen lassen (`access violation` beim Rendern, im Test nach einigen hundert Artikeln).
- Leistungsprotokoll: UI-Blockaden ueber 250 ms landen mit Name und Dauer in `apollo_import_perf.log` im Arbeitsverzeichnis (neben `apollo_import_gui_state.json`), max. 2 MB mit Rotation - hilfreich, wenn etwas langsam wirkt.

## Listenimport CSV/XLSX

Ueber `Produktliste CSV/XLSX` kann eine Liste von Produkten importiert werden. Jeder Eintrag wird ueber `kunzer.de` geladen und direkt in den festen Output-Pfad geschrieben.

Im Bereich `Listenimport` kann ausgewaehlt werden, welche Daten geholt werden sollen:

- `Kurzbezeichnung`
- `Text`
- `Bilder`
- `Dokumente`
- `Videos`
- `Web Links`
- `Attribute` (automatische Attribut-Findung, siehe Abschnitt "Attribute automatisch finden")

Wenn `Kurzbezeichnung` oder `Text` aktiviert sind, wird die Uebersetzung im Listenimport automatisch ueber DeepL ausgefuehrt. Dafuer muss ein gueltiger API Key eingetragen sein.

Ist `Attribute` aktiviert, laeuft pro Artikel die automatische Attribut-Findung:

- sichere, validierte Treffer werden direkt in die `Attribute.xlsx` geschrieben - dabei werden nur Kriterien-IDs ergaenzt, die der Artikel noch nicht hat; bestehende (auch manuell gepflegte) Zeilen bleiben unveraendert
- unsichere Treffer und nicht zugeordnete Angaben landen in der Datei `Attribute_Pruefliste.xlsx` im Output-Ordner
- faellt die KI aus (z. B. fehlender oder ungueltiger API Key), laeuft der Batch regelbasiert weiter; der Hinweis erscheint in der Warnungsliste
- **KI auch bei kurzem Text** (Haken im Abrufumfang, standardmaessig an): Ohne diese Option fragt die Attribut-Findung die KI erst ab 200 Zeichen Text (oder bei unerkannten `Label: Wert`-Zeilen). Viele Shop-Texte sind aber knapp - z. B. MotoMeter `KPS fuer Dieselmotor 10-40 bar mit Druckschlauch, Schnellkupplung` (64 Zeichen): ohne Option kein einziges Attribut, mit Option `Druck von/bis 10/40 bar` plus Zusatzinfo. Kostet ein paar Cent je Artikel; gilt fuer Einzel- und Massenimport.
- **Internet-Recherche auch im Massenimport** (Haken, standardmaessig aus): wie der Button `Automatisch ermitteln (Internet)` - die KI recherchiert je Artikel auf Herstellerseiten und in Datenblaettern (ca. 10-30 ct pro Artikel mit Opus, deutlich laengere Laufzeit; laeuft je Artikel direkt statt ueber die Batch API). Vor dem Start nennt eine Rueckfrage die geschaetzten Kosten; `Nein` startet den Lauf ohne Internet-Recherche.
- **Attribute nach Referenzartikel** (Haken + Feld `Referenzartikel`, standardmaessig aus): Fuer Listen gleichartiger Produkte. Alle Artikel des Massenimports bekommen genau die Attribute des Referenzartikels (ausser Marke) - z. B. mit `0012,8-706R 10` fuer stufenlose Oetiker-1-Ohr-Klemmen: Klemmschellenausfuehrung 3507, Spannbereich 727 (von-bis), Anzahl Teile 9339. Seit v0.1.50 gilt die Vorlage genauso fuer den Einzelartikel: bei `Artikel anlegen` (mit `Attribute` im Abrufumfang) und ueber die Buttons `Attribute automatisch ausfuellen` / `Automatisch ermitteln (Internet)` im Attribute-Tab - vorher wurde der Haken dort nicht beachtet. Treffer ausserhalb der Vorlage erscheinen im Einzelartikel im Bestaetigungsdialog mit dem Hinweis `nicht in der Vorlage (Referenzartikel)` statt in der Maske; die Statuszeile nennt die Vorlage (`Vorlage 0012,8-706R 10: 3 Attribute`) und danach, welche Vorlage-Attribute offen geblieben sind (`Vorlage 0012,8-706R 10: 1 von 3 Attributen nicht gefunden (3507)`). Die Werte kommen weiterhin je Artikel aus Text, KI bzw. Internet-Recherche; die Werte des Referenzartikels bekommt die KI nur als Formatbeispiel (Schluesselwerte mit Bezeichnung, z. B. `1 | Einohrklemme`). Regel- oder KI-Treffer fuer andere Attribute (z. B. Klemmbereich von/bis 3128/3129 oder Zusatzinfo) werden nicht geschrieben, sondern landen in der `Attribute_Pruefliste.xlsx`; aus einem Vorlage-Lauf wird nichts in die `Attribut_Zuordnung.xlsx` gelernt. Solange Vorlage-Attribute fehlen, fragt die App die KI unabhaengig von der Textlaenge. `Aus Maske` uebernimmt die Artikelnummer der Maske. Der Referenzartikel muss im Output-Ordner Attribute haben, sonst startet der Lauf nicht (Einzelartikel: der Button zeigt denselben Hinweis, nach `Artikel anlegen` steht er nur in der Statuszeile und die Findung entfaellt). Ohne Haken entscheidet die KI je Artikel selbst - bei fachlich gleichwertigen Attributen (Spannbereich vs. Klemmbereich von/bis) kann das zwischen gleichartigen Artikeln wechseln. **1:1 aus dem Referenzartikel (seit v0.1.51):** Das Feld `davon 1:1 uebernehmen (Kriterien-IDs)` unter dem Referenzartikel (Standard `9202, 9213, 9220, 9798` = Zusatzinfo, Zusatz LI/SI 2, Information, Entspricht Norm; Komma, Semikolon oder Leerzeichen als Trenner, unbekannte IDs werden mit Hinweis ignoriert) nennt die Attribute, die nicht je Artikel gesucht, sondern mit allen Zeilen des Referenzartikels uebernommen werden - der Referenzartikel wird von Hand gepflegt und ist die Wahrheit. Ab v0.1.58 gilt das nur fuer Zeilen, die die Eingaberegeln einhalten: verstossen die Zeilen einer Kopier-ID schon im Referenzartikel gegen eine Regel (z. B. mehrere Zusatzinfo-Zeilen `9202` - Apollo haelt nur die erste -, Klartext-Schluesselwert, ueber 20 Zeichen, `Wert` gleich `Wert bis`), wird diese ID im Lauf weder kopiert noch gesucht noch ersetzt; die vorhandenen Zeilen der Zielartikel bleiben stehen (Startmeldung bzw. Statuszeile `1:1 nicht uebernommen - Referenzartikel verstoesst gegen eine Eingaberegel: 9202`, vor dem Massenimport mit Rueckfrage). Nach dem Bereinigen des Referenzartikels (ueberzaehlige Texte z. B. nach `9213`/`9220`) ersetzt der naechste Lauf die Zeilen wieder. Diese IDs bekommt weder die Regel-Stufe noch die KI als Kandidaten; vorhandene Zeilen dieser IDs beim Artikel werden durch die Zeilen des Referenzartikels ersetzt - aber nur fuer IDs, zu denen der Referenzartikel wirklich Zeilen hat. Eine Kopier-ID ohne Zeile im Referenzartikel (z. B. `9220`, wenn der Referenzartikel nur Zusatzinfo-Zeilen hat) wird weder kopiert noch gesucht, und vorhandene Zeilen des Artikels dazu bleiben stehen (nichts wird still geloescht); Startmeldung, Statuszeile und Abschlussdialog nennen sie als `ohne Zeile im Referenzartikel: 9220`. Soll eine solche Zeile trotzdem ersetzt werden, bekommt der Referenzartikel eine eigene Zeile dieser ID. Die uebrigen Vorlage-Attribute werden wie bisher gesucht und add-only ergaenzt, und die Attribute des Artikels werden wie beim Referenzartikel sortiert: Marke (8988) zuerst, dann in der Reihenfolge des Referenzartikels, uebrige Zeilen dahinter - auch nach `Uebernehmen` im Bestaetigungsdialog. Ein erneuter Lauf auf demselben Artikel aendert nichts mehr (keine Doppelten). Die Zeilen des Referenzartikels kommen aus der Maske, wenn sie ihn gerade zeigt (eine dort eben gepflegte Zeile gilt sofort), sonst aus dem noch wartenden Live-Schreibauftrag bzw. dem Artikelverzeichnis; der Massenimport loest die Vorlage erst nach Abschluss der Live-Speicherungen auf. Im Einzelartikel erscheinen die 1:1-Zeilen im Bestaetigungsdialog als angehakte Zeilen mit dem Hinweis `aus Referenzartikel <Nr> uebernommen`, die Statuszeile meldet `Vorlage <Nr>: 5 Zeilen 1:1 uebernommen, 3 von 3 gesuchten Attributen gefunden` und, falls Zeilen des Artikels ersetzt wurden, `2 vorhandene Zeilen ersetzt (9202, 9213)`; im Massenimport ersetzt die App die Zeilen in der `Attribute.xlsx`, der Abschlussdialog nennt `Vorlage: n Zeilen 1:1 uebernommen, k vorhandene Zeilen ersetzt`, und der `Attribut-Testbericht.xlsx` fuehrt die 1:1-Zeilen mit Status `Referenz 1:1` sowie jede ersetzte Zeile mit ihrem alten Wert und Status `ersetzt` (Quelle `Referenz`). Der Testlauf berichtet beides (`wuerde ersetzt`), ohne zu schreiben. Die Marke bleibt davon unberuehrt. Feld leeren = nichts 1:1, alles wird gesucht wie bis v0.1.50.
- **Auslaufartikel ueberspringen** (Haken, standardmaessig an): Zeigt kunzer.de statt des Produkts nur `Artikel ist nicht mehr im Sortiment.`, wird nichts uebernommen - im Massenimport stehen diese Artikel in der Warnliste und im Abschlussdialog, nicht in der Loeschliste; im Einzelabruf erscheint ein Hinweis. Ohne die Option landete der Hinweis bisher als Kurzbezeichnung und Text in den Output-Dateien und die Marke wurde `KUNZER`.
- **Testlauf** (standardmaessig aktiv): mit der Checkbox `Testlauf: nur Bericht, nichts schreiben` wird NICHTS in die Attribute.xlsx geschrieben - stattdessen entsteht der vollstaendige `Attribut-Testbericht.xlsx` (je Angabe: Attribut, Wert, Status, Quelle Regel/KI). Ideal, um einen grossen Lauf erst zu pruefen. Der Bericht wird auch im scharfen Lauf als Protokoll geschrieben
- ab 4 Artikeln laufen die KI-Aufrufe gesammelt ueber die Anthropic **Batch API** (50 % Rabatt bei gleicher Qualitaet). Die Artikel werden erst nach dem Batch finalisiert (Attribute schreiben, Pruefliste, Testbericht); waehrend des Wartens zeigt der Fortschritt die Wartezeit und den Stand bei Anthropic, z. B. `KI-Batch 1/1: 0/56 verarbeitet - wartet seit 12 min (Anthropic: in_progress) ...` (Aktualisierung jede Minute)
- **Offener KI-Batch (Sicherung `apollo_import_ki_batch.pkl`)**: Vor dem Einreichen sichert die App die gesammelten KI-Anfragen samt Artikeldaten und danach die Batch-ID in der Datei `apollo_import_ki_batch.pkl` neben dem Programm (wie `apollo_import_gui_state.json`). Ist der Batch nach **2 Stunden** noch nicht fertig, wird er NICHT abgebrochen (er laeuft bei Anthropic weiter und ist bereits bezahlt): der Lauf endet mit dem Hinweis `KI-Batch <ID> nach 2 h noch nicht fertig - die Attribute von N Artikeln koennen spaeter abgeholt werden`, fuer diese Artikel wird nichts geschrieben, die Sicherung bleibt liegen. Dasselbe gilt bei Absturz oder Schliessen waehrend des Wartens. Abholen: Button `KI-Batch abholen` im Massenimport (nur aktiv, solange die Sicherung liegt) oder die Rueckfrage beim naechsten Programmstart (`Ein KI-Batch vom ... mit N Artikeln ist noch offen. Ergebnisse jetzt abholen?`; `Nein` laesst die Sicherung fuer den Button liegen). Das Abholen laeuft wie ein normaler Massenimport (ohne erneuten Kunzer-Abruf), schreibt die Attribute add-only, ergaenzt Pruefliste und Testbericht des urspruenglichen Laufs und loescht die Sicherung; weicht der eingestellte Ausgabeordner von dem des Laufs ab, startet es nicht. `Abbrechen` waehrend des Wartens bricht den Batch bei Anthropic ab, finalisiert die Artikel regelbasiert und loescht die Sicherung. Ein neuer Lauf mit KI-Batch wuerde eine noch liegende Sicherung ueberschreiben - die App fragt vorher nach.
- **Abholen ohne Verlust**: Scheitert die Abfrage eines bereits eingereichten Batches am Claude API Key oder an der Verbindung (Key gewechselt, offline/VPN), bleibt die Sicherung liegen und der Lauf meldet `KI-Batch <ID> konnte nicht abgerufen werden: ... - Sicherung bleibt liegen`; nach dem Beheben einfach erneut `KI-Batch abholen`. Bricht die Finalisierung mittendrin ab (typisch: `Attribute.xlsx` in Excel geoeffnet), bleibt die Sicherung ebenfalls liegen und merkt sich die bereits geschriebenen Artikel - ein erneutes Abholen schreibt nur die restlichen. Artikel, die zwischen Einreichen und Abholen im Verzeichnis geloescht wurden, werden beim Abholen uebersprungen (Hinweis in der Warnliste) statt in der `Attribute.xlsx` wieder angelegt. Zeigt die Maske gerade einen Artikel des Batches, wird sie nach dem Lauf aus den Dateien neu geladen (wie der letzte Artikel eines normalen Massenimports), damit das naechste Live-Speichern die abgeholten Attribute nicht ueberschreibt; hat die Maske ungespeicherte Aenderungen, bleibt sie unveraendert und der Abschlussdialog bittet darum, den Artikel neu zu laden, bevor weiter gespeichert wird.
- der Abschlussdialog zeigt den KI-Verbrauch (Token und ungefaehre Kosten in $)

Unterstuetzte Spalten sind flexibel. Mindestens eine der beiden Gruppen muss vorhanden sein:

- Artikelnummer: `Artikelnummer`, `Produktnummer`, `ArtNr`, `SKU`
- Produkt-URL: `Kunzer Produkt-URL`, `Kunzer URL`, `Produkt-URL`, `URL`, `Link`

CSV-Dateien duerfen mit `;`, `,`, Tab oder `|` getrennt sein. XLSX-Dateien werden aus dem ersten Tabellenblatt gelesen. Neue Artikel werden im festen Importpfad angehaengt; existiert die Artikelnummer bereits, werden nur deren alte Zeilen ersetzt.

## Gefuehrter Modus (Wizard)

Der Button `Gefuehrter Modus` oben rechts startet eine Schrittleiste, die nacheinander durch alle Tabs fuehrt: Artikelnummer, Kurzbezeichnung, Produkttext, GenArt, Attribute, Suchwoerter, OE-Nummern, Vergleichsnummern, Fahrzeuge, Bilder, Dokumente und Links. Zum Schluss zeigt eine Zusammenfassung alle Zaehler und `Exportieren & Fertigstellen` schreibt die Importdateien.

- Pflichtschritte (Artikelnummer, deutsche Kurzbezeichnung, deutscher Produkttext, mindestens eine GenArt, Hersteller je OE-Nummer) lassen erst weiter, wenn sie gueltig sind; die Fehlermeldung erscheint direkt in der Leiste
- Optionale Schritte koennen mit `Weiter` uebersprungen werden
- `Zurueck` und `Beenden` sind jederzeit moeglich; alle Eingaben landen in den normalen Tabs und bleiben erhalten

Damit koennen auch neue Kolleginnen und Kollegen Artikel vollstaendig erfassen, ohne die Reihenfolge oder Pflichtfelder zu kennen.

## Fahrzeugverknuepfungen

Im Tab `Fahrzeuge` koennen einem Artikel Fahrzeuge (KTyp-Nummern) zugeordnet werden. Grundlage ist die KTyp-Stammdatendatei (`KTyp.xlsx`), die im Projekt-Tab unter `Datenstaemme` gewaehlt und jederzeit ueber `Neu laden` aktualisiert werden kann. Standardpfad ist `G:\Apollo\KTyp.xlsx`.

Ablauf:

- einen oder mehrere Motorcodes eingeben (mehrere mit `;` trennen)
- waehrend der Eingabe erscheinen Vorschlaege fuer den gemeinten Motorcode inklusive `meintest du`-Naehe (Tippfehler-tolerant)
- mit `Fahrzeuge hinzufuegen` bzw. `Enter` werden **alle** passenden Fahrzeuge aus den Stammdaten uebernommen (Hersteller, Modell, Bezeichnung, Bauzeit, Leistung, KTyp TopMotive und KTyp TecDoc)
- der Fahrzeugtyp ist per Dropdown waehlbar; Standard ist `PKW (2)`, weitere sind `NKW (16)`, `Motor (14)` und `Achse (19)`

Die Suche ueber Motorcodes ist robust gegen Gross-/Kleinschreibung, Leerzeichen und Klammerzusaetze (z. B. `108C (XV8)` findet auch `108C`).

Der Export erzeugt `Fahrzeugverknuepfungen.xlsx` mit den Spalten:

- `Artikelnummer`
- `Fahrzeugtyp` (fuer den Apollo-Import auf `TecDoc Verknuepfungstyp ID` mappen, `PKW = 2`)
- `KTypNr` (fuer den Apollo-Import auf `TecDoc Verknuepfungs ID` mappen)
- `KTyp-System` (immer `TecDoc`)
- `GenArt ID` und `GenArt Bezeichnung` (die GenArt, mit der das Fahrzeug verknuepft ist)

Je Fahrzeug und verknuepfter GenArt wird eine Zeile mit der **TecDoc-Nummer** geschrieben (ab v0.1.53). Die TopMotive-Nummer steht nur in der Maske: Der IMS-Import liest `KTypNr` immer als TecDoc-KTyp, und die beiden Nummernkreise ueberschneiden sich - eine TopMotive-Nummer verknuepfte in Apollo ein anderes Fahrzeug (z. B. TopMotive 23900 = BMW 1er F20 125i, TecDoc 23900 = Mercedes E-Klasse W211). Bis v0.1.52 wurde jedes Fahrzeug mit TopMotive- und TecDoc-Nummer und mit allen GenArts des Artikels geschrieben (voller Export der 99 IMS-Artikel: 136.759 statt 41.392 Zeilen, 692 falsche Fahrzeuge in Apollo); die Datei auf `G:\Apollo\GUI` wurde am 29.10.2026 bereinigt.

Fahrzeuge ohne TecDoc-Nummer (in der `KTyp.xlsx` nur ein Topmotive-eigener Eintrag) werden nicht exportiert und auch nicht gespeichert - die Datei fuehrt nur TecDoc-Nummern; ein solches Fahrzeug steht nur bis zum Verlassen des Artikels in der Maske (Meldung beim Hinzufuegen: `... davon ohne TecDoc-Nummer - werden nicht gespeichert und nicht nach Apollo exportiert.`). Das zeigen die Spalte `GenArt` (`nicht exportiert (keine TecDoc-Nr.)`), die Ergebniszeile im Tab `Fahrzeuge` (beim Hinzufuegen und nach dem Laden: `Fahrzeuge: n ohne TecDoc-Nummer, nicht exportiert.`) und die Zusammenfassung des gefuehrten Modus (`Fahrzeuge: 706 (1 ohne TecDoc-Nummer, nicht exportiert)`).

Alte Zeilen mit `KTyp-System = Topmotive` werden ueber die KTyp-Stammdaten ihrem TecDoc-Fahrzeug zugeordnet (GenArts beider Zeilen vereinigt) und beim naechsten Schreiben des Bereichs als TecDoc-Zeilen geschrieben. Sind die KTyp-Stammdaten beim Laden noch nicht da (erster Start nach einem Update - der Katalog-Cache gilt je Programmversion - oder nach einer Aenderung der `KTyp.xlsx`), steht ein solches Fahrzeug vorerst zweimal in der Maske: einmal nur mit TopMotive-Nummer (Spalte `GenArt`: `wartet auf KTyp-Stammdaten`), einmal nur mit TecDoc-Nummer. Kommt der Katalog, fuehrt die Maske beide zusammen wie beim Laden mit Katalog - ohne Eingabe wird dabei nichts geschrieben. Eine Eingabe in der Zwischenzeit (z. B. GenArt entfernt) schreibt die Fahrzeuge nicht ohne diese Fahrzeuge: der Bereich wartet wie ein gescheiterter (`<Artikel>: Fahrzeugverknuepfungen warten auf die KTyp-Stammdaten ... - sie werden gespeichert, sobald die Stammdaten geladen sind`), der Artikel darf verlassen werden, und sobald der Katalog geladen ist, schreibt die App die Fahrzeuge mit den TecDoc-Nummern (auch fuer verlassene Artikel). Einzelne Fahrzeuge entfernen und `Exportieren & Fertigstellen` bitten solange um etwas Geduld (Meldung), weil die beiden Haelften eines Fahrzeugs erst mit dem Katalog zusammenfinden. Ist gar kein KTyp-Katalog verfuegbar, bleibt der Bereich offen (Warnung beim Beenden), statt Fahrzeuge still wegzulassen.

Welche GenArts ein Fahrzeug hat, zeigt die Spalte `GenArt` im Tab `Fahrzeuge` (`alle`, die einzelnen IDs, `-` ohne GenArt am Artikel):

- Jedes Fahrzeug behaelt beim Laden seine GenArts aus der Datei - aus IMS (`IMS-Export uebernehmen`) haengen viele Fahrzeuge nur an einem Teil der GenArts des Artikels. Unveraenderte Fahrzeuge werden deshalb Zeile fuer Zeile so zurueckgeschrieben, wie sie geladen wurden: Laden, Artikelwechsel und `Exportieren & Fertigstellen` eines unveraenderten Artikels aendern die Datei nicht (Inhalt, Reihenfolge, Zeitstempel).
- Wird im Tab `GenArt` eine GenArt geloescht, fallen alle Fahrzeugzeilen dieser GenArt weg. Fahrzeuge, die danach an keiner GenArt mehr haengen, verschwinden auch aus Maske und Verzeichnis (wie nach dem Neuladen aus der Datei) - vorher fragt die App: `Mit GenArt <ID Bezeichnung> fallen <n> Fahrzeug(e) weg, die nur an dieser GenArt haengen (ihre Zeilen in Fahrzeugverknuepfungen.xlsx werden geloescht). Tipp: Soll die GenArt ersetzt werden, zuerst die neue GenArt hinzufuegen, dann die alte entfernen - dann behalten die Fahrzeuge ihre Verknuepfung. Trotzdem entfernen?` (Warnsymbol, Vorauswahl `Nein`; `Nein` aendert nichts, die Statuszeilen nennen nach `Ja` die Zahl). Blieben solche Fahrzeuge mit `keine` in der Maske stehen, kaemen sie mit der naechsten neuen GenArt in derselben Sitzung zurueck in die Datei, nach einem Neustart aber nicht (so in der Entwicklungsfassung von v0.1.53).
- Das gilt auch fuer die letzte GenArt und `Alle GenArten entfernen`: danach hat der Artikel keine Fahrzeuge mehr - es entstehen keine Zeilen ohne GenArt.
- Dieselben Regeln gelten, wenn GenArten im Reiter `Uebersicht` auf mehrere Artikel uebertragen werden (`GenArten einfuegen...`, siehe `Uebersicht`).
- Wird eine GenArt hinzugefuegt (auch eine eben entfernte), wird sie mit allen Fahrzeugen des Artikels verknuepft - auch nach Artikelwechsel oder Neustart.
- Neu ueber Motorcodes hinzugefuegte Fahrzeuge bekommen alle GenArts des Artikels. Hat ein Artikel (noch) nie eine GenArt gehabt, wird wie bisher je Fahrzeug eine Zeile ohne GenArt geschrieben; die erste GenArt verknuepft dann alle Fahrzeuge.
- Zeilen, die nicht zu den GenArts des Artikels passen - GenArt nicht (mehr) am Artikel, z. B. nach einer Aenderung ausserhalb der GUI, oder eine Zeile ohne GenArt neben GenArt-Zeilen desselben Fahrzeugs -, gehen nicht still verloren: die Ergebniszeile im Tab `Fahrzeuge` nennt sie beim Laden, bis die Fahrzeuge des Artikels das naechste Mal geschrieben sind (`Hinweis: n Zeile(n) in Fahrzeugverknuepfungen.xlsx passen nicht zu den GenArts des Artikels ...`). Beim naechsten Speichern der Fahrzeuge gilt die Spalte `GenArt`: ein Fahrzeug mit mindestens einer GenArt des Artikels behaelt genau diese, ein Fahrzeug ganz ohne passende GenArt gilt wie ein neues (mit allen GenArts des Artikels). In den bereinigten Echtdaten (29.10.2026) kommt das nicht vor.

Bestehende `Fahrzeugverknuepfungen.xlsx` ohne GenArt-Spalten (altes Format mit 5 Spalten) werden beim Laden erkannt: jedes Fahrzeug gilt als mit allen GenArts des Artikels verknuepft (die Ergebniszeile im Tab `Fahrzeuge` sagt das neutral: `Hinweis: n Zeile(n) ... ohne GenArt (altes Dateiformat) ...`, nicht `passen nicht`), `Zuletzt geschrieben am` kommt aus der richtigen Spalte (die Entwicklungsfassung von v0.1.53 las den Zeitstempel als GenArt, und das naechste Speichern verlor alle Fahrzeuge des Artikels). Beim naechsten Schreiben wird die Datei auf das neue Format migriert.

## Stueckliste und Zubehoerliste

Reiter `✎ Stückliste/Zubehör` - entspricht in IMS dem Reiter `Artikelliste(n)` mit den Listentypen `Stückliste` und `Zubehörliste`:

- **Stückliste**: was im Lieferumfang enthalten ist, mit Menge (z. B. Heber `AJ-45T3GFL`: 1x `02041`, 2x `02042`).
- **Zubehörliste**: optionales Zubehoer (Menge in der Regel 1).

Je Position: Typ, `Lieferantenartikelnummer` (Listenartikel), `Menge`, `TecDoc GenArt ID` und `Produktgruppe` **des Listenartikels** (nicht des Hauptartikels) und `Sort Nr`. Beim Eingeben der Artikelnummer schlaegt die App Artikel aus dem Artikelverzeichnis vor und belegt GenArt und Produktgruppe aus der gespeicherten GenArt des Listenartikels vor (bei mehreren GenArts zur Auswahl). Steht der Listenartikel nicht im Output, GenArt-ID von Hand eingeben - die Produktgruppe kommt dann aus dem GenArt-Katalog. Die `Sort Nr` zaehlt je Artikel und Typ ab 1 in der Reihenfolge der Tabelle; mit ▲/▼ innerhalb eines Typs umsortieren.

Geschrieben wird live in `Artikellisten.xlsx` (Blatt `Artikellisten`): `Artikelnummer`, `Typ`, `Lieferantenartikelnummer`, `Menge`, `TecDoc GenArt ID`, `Produktgruppe`, `Sort Nr`, `Zuletzt geschrieben am`. Wie GenArt, OE-Nummern und Attribute zaehlen die Listen zu den gepflegten Daten: Massenimport und Kunzer-Abruf lassen sie unveraendert, Loeschen im Artikelverzeichnis entfernt die Listen des Artikels (nicht seine Verwendung in Listen anderer Artikel). Abgelehnt werden: Menge keine ganze Zahl ab 1, GenArt fehlt bzw. keine Zahl, der Artikel selbst als Listenartikel, dieselbe Position zweimal im selben Typ. Das Artikelverzeichnis zeigt die Anzahl in der Spalte `Listen`; die Suche findet einen Artikel auch ueber die Nummern seiner Listenartikel.

## Attribute automatisch finden

Die Attribut-Findung arbeitet hybrid in zwei Stufen und wird ueber den Button `Attribute automatisch ausfuellen` im Attribute-Tab oder automatisch nach dem Kunzer-Laden gestartet - Letzteres nur, wenn `Attribute` im Abrufumfang angehakt ist (bis v0.1.45 lief sie nach jedem `Artikel anlegen`, auch bei reinem Bild-Umfang, und verursachte dabei KI-Kosten). Der KI-Nachlauf fuer Suchwoerter laeuft davon unabhaengig.

Ist im Abrufumfang `Attribute nach Referenzartikel` angehakt, gilt die Attribut-Vorlage des Referenzartikels seit v0.1.50 auch fuer den Einzelartikel (Button und `Artikel anlegen`), nicht nur im Massenimport: gefunden und uebernommen werden nur die Attribute des Referenzartikels, Treffer fuer andere Attribute gehen mit dem Hinweis `nicht in der Vorlage (Referenzartikel)` in den Bestaetigungsdialog, die KI wird nur gefragt, solange Vorlage-Attribute fehlen, und die Statuszeile nennt die nicht gefundenen Vorlage-Attribute (Details im Abschnitt "Listenimport CSV/XLSX"). Seit v0.1.51 werden die Kriterien-IDs aus `davon 1:1 uebernehmen` (Standard Zusatzinfo 9202, Zusatz LI/SI 2 9213, Information 9220, Entspricht Norm 9798) nicht gesucht, sondern mit allen Zeilen des Referenzartikels uebernommen: vorhandene Zeilen dieser IDs werden ersetzt (nur fuer IDs, zu denen der Referenzartikel Zeilen hat; ersetzte Zeilen nennt die Statuszeile), die Attribute wie beim Referenzartikel sortiert (Marke zuerst, auch nach `Uebernehmen` im Bestaetigungsdialog), und die KI bekommt diese IDs nicht als Kandidaten - Zusatzinfos werden dann nicht mehr je Artikel auf die Slots 9202/9213/9220 verteilt. Zeigt die Maske gerade den Referenzartikel, zaehlen ihre Zeilen (eine eben gepflegte Zeile gilt sofort). Ab v0.1.58 werden Kopier-IDs, deren Zeilen im Referenzartikel selbst gegen eine Eingaberegel verstossen (z. B. mehrere `9202`-Zeilen), nicht 1:1 uebernommen (siehe `Listenimport CSV/XLSX` und `Eingabepruefung und Pruefung vor dem Import`).

PDF-Dokumente des Artikels fliessen als Text mit ein. Ab v0.1.49 werden bei mehrseitigen PDFs nur die Seiten verwendet, auf denen die eigene Artikelnummer steht; steht sie auf keiner Seite, wird das PDF ignoriert. Vorher uebernahm die Findung aus einer Broschuere, die an allen Artikeln einer Serie haengt (WES-Werkstattmodule), die Werte fremder Produkte - 54 WES-Artikel bekamen so die Kabellaenge des LED-Adapters und die Laenge von Modul 1. Einseitige PDFs (Datenblaetter) gelten immer als artikelbezogen.

**Stufe 1 - Regeln (immer aktiv, kostenlos):** Erkannt werden `Label: Wert`- und Tab-getrennte Zeilen aus Technische-Daten-Bloecken, z. B.:

- `Gewicht: 612 g` -> `Gewicht [kg]` = `0,612` (Einheiten werden automatisch umgerechnet)
- `Hubhoehe: 150 - 530 mm` -> Bereich als `Wert` + `Wert bis`
- `Abmessungen (LxBxH): 155 x 17 x 13,5 mm` -> aufgeteilt in `Laenge`, `Breite`, `Hoehe`
- Schluesselwert-Attribute werden nur uebernommen, wenn der Wert in der Schluesselliste des Kriteriums (eigene Herkunft, siehe `Eingabepruefung und Pruefung vor dem Import`) genau eine Bezeichnung trifft - ab v0.1.58 zuerst die Bezeichnung, nie still ein nacktes Kuerzel (eine Zahl im Text ist ein Wert: `Akkuspannung: 12 V` wird nicht mehr Kuerzel `12` = 7,2), kein Teiltreffer; Doppeldeutiges geht mit Hinweis in den Bestaetigungsdialog bzw. die Pruefliste
- Normbezeichnungen mit Ausgabejahr wie `EN ISO 374-1:2016/TYPE B` (DIN, EN, ISO, IEC, ANSI, ASTM, VDE, UL) gelten seit v0.1.51 nicht als `Label: Wert`-Zeile - der Doppelpunkt gehoert zur Norm, die Zeile bleibt Freitext fuer die KI. Vorher wurde ueber die gelernte Zuordnung `EN ISO 374-1 -> 9798` der Wert `2016/TYPE B` als `Entspricht Norm` uebernommen. `Norm: EN ISO 374-1:2016` (Label `Norm`) funktioniert weiterhin.

Grundlage ist die pflegbare Zuordnungsdatei `Attribut_Zuordnung.xlsx` (Standard `G:\Apollo\Attribut_Zuordnung.xlsx`, Spalten `Text-Label` und `TecDoc Kriterien ID`), die im Projekt-Tab unter `Datenstaemme` konfiguriert wird. Welche Schluesselliste ein Schluesselwert-Kriterium benutzt, steht ab v0.1.58 in der eigenen Datei `Schluessellisten_Zuordnung.xlsx` (Datenstaemme-Zeile `Schluessellisten-Zuordnung XLSX`, siehe `Eingabepruefung und Pruefung vor dem Import`).

**Stufe 2 - Claude-KI (optional, braucht Anthropic API Key):** Alles, was die Regeln nicht zuordnen konnten (Fliesstext, Synonyme, unbekannte Labels), geht zusammen mit dem Text der verlinkten PDF-Dokumente an die Claude API. Ueber den zweiten Button `Automatisch ermitteln (Internet)` recherchiert die KI zusaetzlich per Websuche auf Herstellerseiten und in Datenblaettern (ca. 10-30 ct pro Artikel; im Massenimport ueber die Option `Internet-Recherche auch im Massenimport`, siehe unten). Auch Recherche-Treffer zaehlen nur, wenn sie eindeutig zum Artikel gehoeren und die lokale Validierung bestehen. Die KI bekommt dabei nur eine lokal vorgefilterte Kandidatenliste (max. 300 plausible Attribute statt aller ~5.000) - das haelt die Kosten klein. Der API Key und das Modell werden im Projekt-Tab unter `APIs` eingestellt (auch per Umgebungsvariable `ANTHROPIC_API_KEY`); Standardmodell ist `claude-opus-4-8`, guenstigere Modelle sind waehlbar.

**Ohne Text in der Maske:** Ist kein deutscher Text erfasst (z. B. weil die Texte bereits in Apollo gepflegt sind), holt sich die Attribut-Findung den Produkttext selbst von kunzer.de - nur zum Auswerten. Gespeichert wird er nirgends; Texte, IDs und alle anderen Daten bleiben unangetastet.

**Gestufte Uebernahme:** Jeder Treffer - egal ob aus Regeln oder KI - wird lokal streng gegen die Attribut-Stammdaten validiert (Zahlformat, Einheiten-Umrechnung, Schluesselwert in der Schluesselliste des Kriteriums, maximale Laenge; ab v0.1.58 zusaetzlich die Eingaberegeln der Maske: hoechstens 20 Zeichen je Wert, kein Bereich mit `Wert` gleich `Wert bis`, je Artikel nur eine Zeile `9202`/`9213`/`9220`). Nur validierte Treffer werden automatisch uebernommen, und nur fuer Kriterien-IDs, die der Artikel noch nicht hat (bestehende Zeilen werden nie ueberschrieben). Unsichere Treffer erscheinen wie bisher im Bestaetigungsdialog; dort koennen nicht erkannte Angaben manuell zugewiesen und mit `Zuordnung merken` dauerhaft gelernt werden.

**Zusatzinfo-Slots als Auffangbecken:** Wichtige technische Angaben, die zu keinem Attribut passen, liefert die KI als kurze Stichworte (max. 20 Zeichen, z. B. `IP54`, `inkl. Koffer`). Da Apollo je Artikel nur eine Zeile je Freitextfeld haelt (ab v0.1.58 nimmt die GUI auch keine zweite mehr an), verteilt die App die wichtigsten Infos auf drei Slots: `9202 Zusatzinfo`, `9213 Zusatz LI/SI 2`, `9220 Information`. Weitere Infos landen im Pruefdialog bzw. in der Pruefliste.

**Label-Mining (Selbst-Training):** Der Button `Labels per KI zuordnen` bei den Datenstaemmen analysiert alle Texte im Output-Ordner, sammelt unbekannte Text-Labels samt Beispielwerten und laesst die KI sie EINMALIG zuordnen. Uebernommen wird nur, was an echten Beispielwerten lokal validiert wurde (Hinweis `KI-Miner` in der Zuordnungsdatei); der Rest landet in der `Label-Zuordnung-Pruefliste.xlsx`. Danach loest die kostenlose Regel-Stufe diese Labels ohne KI-Aufruf - der Grossteil aller Spezifikationszeilen wird damit gratis.

**Lernschleife:** Ordnet die KI ein neues Text-Label erfolgreich zu (z. B. `Farbton` -> `Farbe`), wird die Zuordnung mit Hinweis `KI` in die `Attribut_Zuordnung.xlsx` geschrieben. Beim naechsten Artikel greift dann schon die Regel-Stufe - ohne API-Aufruf. KI-Eintraege sind in der Datei ueber die Hinweis-Spalte auffindbar und koennen dort jederzeit korrigiert oder geloescht werden.

Die KI erhaelt den Produkttext als reinen Inhalt und darf nur Attribute aus der mitgeschickten Kandidatenliste waehlen; alles andere wird verworfen. Ohne API Key (oder bei API-Fehlern) laeuft die Findung vollstaendig regelbasiert weiter.

## Marke (Attribut 8988)

Die Marke eines Artikels wird in Apollo als Attribut `8988 Marke` (Format `Alphanumerisch`, max. 20 Zeichen) gepflegt. Bei jedem Kunzer-Abruf - im Einzelartikel (`Artikel anlegen`) wie im Massenimport (`Liste importieren`, `Artikelliste aktualisieren`) - setzt die App diese Zeile automatisch, rein lokal und ohne KI-Aufruf. Die Marke steht auf kunzer.de nicht im Seitentext, sondern wird aus den Signalen der Produktseite erkannt, in dieser Reihenfolge (der erste Treffer gewinnt):

1. **Medienordner**: erstes Pfadsegment der `restapi.kunzer.de`-Links von Bildern und Dokumenten, z. B. `airman`, `tdl`, `weber hydraulik`, `moto meter`, `norma`, `oetiker`, `argus - batterietester` oder `kunzer werkzeuge` (Ordner ohne Marke aus der Liste, z. B. `suprabeam` oder `handschuhe`, zaehlen nicht). Nennt der Ordner `KUNZER`, gewinnt trotzdem eine Fremdmarke aus dem Kategoriepfad oder aus den ersten Woertern von Titel/Kurzbezeichnung (z. B. `Oetiker Montagezange ...` im Ordner `kunzer werkzeuge` -> `OETIKER`), aus einem Link-Label, das mit der Marke beginnt (`Oetiker - Lochbandklemmen 259 - DualHook`; `Anleitung Oetiker-Zange` zaehlt nicht), oder ein einzelnes Bild/Dokument im Ordner einer Fremdmarke neben der Kunzer-Mehrheit (DualHook `18500260`-`18500267`: drei Bilder in `kunzer werkzeuge`, eins in `oetiker` -> `OETIKER`). Shop-Suchwoerter und Langtext zaehlen in diesem Fall nicht - dort stehen Gattungsnamen wie `Oetiker-Zange` auch bei Kunzer-Produkten
2. **Kategoriepfad** der Produktseite (Breadcrumb), z. B. `Produkte > Werkzeuge > Rad und Reifen > airMAN` oder `Produkte > Hebetechnik > Lufthydraulische Heber T D L`
3. **Shop-Suchwoerter** des Artikels (Feld `SUCHWOERTER` der Produktdaten, z. B. `Dichtmilch;Pannenpilot;Airman`)
4. **Titel, Kurzbezeichnung, Text** - Treffer nur an Wortgrenzen (`Norma` trifft nicht `normal`); `KUNZER` zaehlt in Texten nicht als Treffer, weil es ohnehin der Standard ist
5. **Link-Labels** der Produktseite (z. B. `AIRMAN - 71-051-011`)
6. ohne Treffer: `KUNZER` (Kunzer-Eigenartikel tragen zudem EAN mit GS1-Praefix `4260174`)

Erkannt werden nur Marken aus der **Markenliste** (Einstellungen, Tab `API & Datenstaemme`, Block `Marke (Attribut 8988)`). Jeder Eintrag nennt den kanonischen Namen, der in die `Attribute.xlsx` geschrieben wird - das ist die Schreibweise der Apollo-Liste `Product Brand Name` - und optional Schreibweisen (Aliasse): Eintraege mit `;` trennen, Aliasse nach `=` mit `,` - Gross-/Kleinschreibung spielt keine Rolle, Leerzeichen und Bindestriche in Aliassen sind beliebig (`T D L` trifft auch `TDL`, `weber hydraulik` auch `Weber-Hydraulik`). Standard:

```
KUNZER; OETIKER; T D L=tdl; JOKON; Airman=air man; MOTO METER=motometer,moto-meter; WEBER=weber hydraulik,weber-hydraulik; ARGUS; NORMA
```

Die Liste wird mit dem Sitzungszustand gespeichert; `Standard` stellt die eingebaute Liste wieder her (eine gespeicherte unveraenderte Standardliste aus v0.1.36 wird automatisch ersetzt). Kanonische Namen muessen in 20 Zeichen passen (laengere werden abgeschnitten).

**Schreibweise angleichen:** Steht in einer vorhandenen `8988`-Zeile eine Marke der Liste in anderer Schreibweise (z. B. `MotoMeter`, `TDL`, `Kunzer`, `Weber Hydraulik`), bringt der naechste Kunzer-Abruf bzw. Massenimport des Artikels sie auf die Schreibweise der Liste (`MOTO METER`, `T D L`, `KUNZER`, `WEBER`). Werte, die keiner Marke der Liste entsprechen, bleiben unveraendert.

Verhalten:

- **Manuelle Pflege gewinnt:** Hat der Artikel bereits eine `8988`-Zeile mit Wert (in der `Attribute.xlsx` bzw. im Artikelverzeichnis), bleibt sie unveraendert - die erkannte Marke wird nie darueber geschrieben. Nur eine leere `8988`-Zeile wird ersetzt. Pro Artikel gibt es genau eine `8988`-Zeile; die automatische Attribut-Findung legt keine zweite an.
- **Einzelabruf:** Bis v0.1.35 wurden beim `Artikel anlegen` Attribute, GenArt, OE-/Vergleichsnummern, Fahrzeuge und alle nicht abgerufenen Texte/Medien der Maske geleert und dieser Leerstand live geschrieben - vorhandene Daten des Artikels gingen damit verloren. Jetzt kommt alles, was nicht neu von kunzer.de abgerufen wird, aus dem gespeicherten Stand des Artikels (inkl. noch nicht geschriebener Aenderungen); die gespeicherten Attributzeilen bleiben erhalten (Grundlage ist der gespeicherte Stand des Artikels, nicht die Maske: zeigt die Maske noch einen zuvor geladenen anderen Artikel, gehen dessen Zeilen nicht auf den neuen Artikel ueber), die Marke wird ergaenzt und zusammen mit den uebrigen Daten live gespeichert - auch wenn nur Medien im Abrufumfang sind.
- **Massenimport:** Die Marke wird fuer jeden Artikel ergaenzt (add-only in die `Attribute.xlsx`), unabhaengig von der Option `Attribute (automatisch, Regeln + KI)` und auch im Testlauf. Der Abschlussdialog nennt, wie viele Artikel eine Marke bekommen haben und wie viele schon eine hatten; der `Attribut-Testbericht.xlsx` enthaelt je Artikel die erkannte Marke mit Signal (Status `automatisch` bzw. `vorhanden`, Quelle `Marke`).
- **Ungueltige vorhandene Attributzeile:** Bricht eine gespeicherte Zeile die Formatpruefung (z. B. Bereich mit vertauschtem von/bis), kann der Artikel keine Attribute speichern - auch die Marke nicht. Die App meldet das nach dem Abruf in einem Hinweis; nach der Korrektur im Tab `Attribute` wird automatisch gespeichert. Suchwoerter werden davon unabhaengig geschrieben. Die Eingaberegeln ab v0.1.58 (Schluesselwert aus der Liste, hoechstens 20 Zeichen, `Wert` gleich `Wert bis`, Freitextfeld mehrfach) sperren dagegen nichts: solche vorhandenen Zeilen werden nur markiert und von `Pruefung vor dem Import...` gemeldet.
- **Massenimport bei gesperrter `Attribute.xlsx`** (z. B. in Excel geoeffnet): Der Marken-Schritt setzt nach dem ersten Fehler fuer den Rest des Laufs aus, der Abschlussdialog nennt die Zahl der Artikel ohne Marke.
- **Pflege in der Uebersicht (ab v0.1.54, ab v0.1.55 direkt in der Zelle):** In der Spalte `Marke` des Reiters `Uebersicht` wird die Marke wie in Excel in der Zelle gewaehlt oder getippt (Schreibweise der Markenliste wird uebernommen) und gilt sofort fuer alle markierten Zeilen; `Strg+C`/`Strg+V` kopieren und setzen sie, `Strg+Z` macht es rueckgaengig. Das setzt die `8988`-Zeile und zieht mit dem Haekchen `Marke auch als Suchwort` die Suchwoerter mit (alte Marke samt Schreibweisen raus, neue Marke als erstes Suchwort) - siehe `Uebersicht` > `Marke direkt in der Zelle`.

## Suchwoerter

Suchwoerter sind in Apollo Referenzen vom Typ `Gebrauchsnummer` (Reiter `Referenzen`, Typ mit TecDoc ID `2`); das Suchwort steht als Freitext in der Spalte `Nummer`. Im Tab `Suchwoerter` koennen deshalb pro Artikel freie Suchbegriffe gepflegt werden, die beim Export in eine eigene Referenzdatei geschrieben werden:

- jedes Suchwort wird eine eigene Zeile in `Gebrauchsnummern.xlsx`
- Spalten: `Artikelnummer`, `TecDoc ID` = `2`, `Gebrauchsnummer` = Suchwort (gleicher Aufbau wie `OE-Nummern.xlsx`, nur ohne Hersteller-ID)
- maximal 35 Zeichen pro Suchwort (ab v0.1.58, vorher 50 - Apollo schneidet laengere ab oder lehnt sie ab); laengere Eingaben werden abgewiesen. Vorhandene laengere Suchwoerter bleiben stehen, bis sie geaendert werden: sie stehen in roter Schrift im Reiter, der Zaehler nennt sie, und `Pruefung vor dem Import...` meldet sie
- mehrere Suchwoerter koennen mit `;` getrennt auf einmal eingegeben werden
- Duplikate werden automatisch ignoriert

Bis v0.1.31 wurden Suchwoerter faelschlich als Attribut `Zusatzbezeichnung` (Kriterien ID `9595`) in die `Attribute.xlsx` geschrieben. Solche Altzeilen werden beim Laden aus den Output-Dateien weiterhin als Suchwoerter erkannt und beim naechsten Speichern der Suchwoerter des Artikels nach `Gebrauchsnummern.xlsx` ueberfuehrt; aus der `Attribute.xlsx` verschwinden sie dabei. Werden in der Maske nur die Attribute gespeichert (z. B. nur die Marke geaendert), bleiben die Altzeilen, deren Wort die Maske noch als Suchwort fuehrt, unveraendert stehen und wandern erst mit den Suchwoertern um - bis v0.1.54 gingen die Alt-Suchwoerter in diesem Fall verloren, weil das Ersetzen der Attributzeilen sie mit entfernte. Ebenso bleiben sie stehen, wenn das Schreiben der `Gebrauchsnummern.xlsx` scheitert (z. B. in Excel geoeffnet); das Nachholen zieht sie dann um. Sind die Suchwoerter geschrieben, scheitert aber die `Attribute.xlsx`, gelten beide Bereiche als nicht gespeichert: das Nachholen schreibt beide und raeumt die Altzeilen (sonst kaemen eben entfernte Alt-Suchwoerter nach dem Neuladen zurueck). Die Markenaenderung in der Uebersicht und der Suchwort-Import ziehen sie gleich mit um.

### Import aus Excel/CSV

Ueber `Aus Datei importieren…` im Tab `Suchwoerter` lassen sich Suchwoerter fuer viele Artikel auf einmal aus einer XLSX- (Blatt 1) oder CSV-Datei (Trennzeichen automatisch, utf-8 oder Windows-1252) uebernehmen. Nach der Dateiauswahl zeigt ein Dialog die Vorschau (Anzahl Artikel und Suchwoerter, uebersprungene Eintraege, Artikel, die noch nicht im Verzeichnis stehen) und fragt den Modus ab:

- `Ergaenzen`: vorhandene Suchwoerter der betroffenen Artikel bleiben, neue kommen dazu (Duplikate ohne Gross-/Kleinschreibung werden ignoriert)
- `Ersetzen`: die Suchwoerter der in der Datei genannten Artikel werden komplett durch die Datei ersetzt
- Artikel, die nicht in der Datei stehen, bleiben in beiden Faellen unberuehrt; Artikel, die noch nicht im Verzeichnis sind, werden nur mit ihren Suchwoertern angelegt

Akzeptierte Spalten (Kopfzeile Pflicht, Gross-/Kleinschreibung egal):

- Artikelspalte: `Artikelnummer`, `ArtikelNr`, `ArtNr`, `Produktnummer`, `SKU` oder `Article`; numerische Zellen (z. B. `14100501`) werden als Text uebernommen
- Suchwortspalte(n): `Suchwort`, `Suchwoerter`, `Suchbegriff(e)`, `Gebrauchsnummer(n)`, `Keyword(s)` oder `Nummer` - auch mehrere Spalten wie `Suchwort 1`, `Suchwort 2`, `Keyword 3`, die zusammengefuehrt werden; eine exportierte `Gebrauchsnummern.xlsx` laesst sich damit direkt wieder einlesen
- eine Zelle darf mehrere Suchwoerter enthalten, getrennt durch `;`, `|`, Zeilenumbruch oder Komma - ein Komma zwischen zwei Ziffern trennt nicht, `10,5 mm` oder `1,5 Zoll` bleiben ein Suchwort
- bei CSV-Dateien bestimmt die Kopfzeile das Trennzeichen (`;`, `,`, Tab oder `|`); ueberzaehlige Zellen einer Datenzeile (z. B. `14100501;Bremse;Scheibe` ohne Anfuehrungszeichen) zaehlen zur letzten Suchwortspalte, wenn diese die letzte Spalte der Kopfzeile ist - sonst werden sie als "ohne Spaltenkopf" uebersprungen und in Vorschau und Zusammenfassung genannt
- fehlt die Artikelspalte, gelten alle Suchwoerter fuer den Artikel, der gerade in der Maske steht (ohne Artikelnummer in der Maske bricht der Import mit Hinweis ab); fehlt die Suchwortspalte bei genau zwei Spalten, gilt die Spalte neben der Artikelnummer als Suchwortspalte
- leere Eintraege und Suchwoerter ueber 35 Zeichen werden uebersprungen und in der Zusammenfassung aufgefuehrt

Der Import schreibt die `Gebrauchsnummern.xlsx` in einem Zug (Zeitstempel unveraenderter Zeilen bleiben erhalten) und aktualisiert Artikelverzeichnis und Maske direkt, ohne alle Output-Dateien neu zu laden; vorher gleicht er das Verzeichnis einmal mit dem Ausgabeordner ab, damit die Vorschau die noch nicht vorhandenen Artikel richtig zaehlt. Alt-Suchwoerter (Kriterien-ID `9595` in der `Attribute.xlsx`) liest der Import direkt aus der Datei: beim Ergaenzen wandern sie mit in die `Gebrauchsnummern.xlsx`, beim Ersetzen entfallen sie, ihre Altzeilen verschwinden in beiden Faellen aus der `Attribute.xlsx`. Ist die `Attribute.xlsx` dabei gesperrt (z. B. in Excel geoeffnet), bleiben die Suchwoerter trotzdem vollstaendig importiert; die Zusammenfassung weist darauf hin, und ein erneuter Import derselben Datei raeumt die Altzeilen nach.

### Automatisch erzeugen

Suchwoerter entstehen auch ohne Tippen - regelbasiert immer, per KI optional:

- **Beim Kunzer-Laden** (`Artikel anlegen`): die Maske zeigt die bereits gespeicherten Suchwoerter des Artikels plus die regelbasierten Kandidaten; nichts wird geloescht. Quellen in dieser Reihenfolge: die Marke (Wert des Attributs `8988 Marke`), die Shop-Suchwoerter von kunzer.de (Feld `SUCHWOERTER` der Produktseite, z. B. `Dichtmilch;Pannenhilfe;Airman`), die GenArt-Bezeichnungen des gespeicherten Standes (Komma-Listen wie `Dichtmittel-Set, Reifen-Dichtungs-Set` je Variante einzeln) und die Woerter der Kurzbezeichnung (ohne Fuellwoerter, Artikelnummer, Zahlen/Masse/Codes; Bindestrich-Komposita wie `Motor-Einstellwerkzeugsatz` zusaetzlich als Ganzes und in ihren Teilen). Das Live-Speichern schreibt die Suchwoerter mit dem Artikel in die `Gebrauchsnummern.xlsx`.
- **Button `Suchwoerter automatisch`** im Tab `Suchwoerter`: zeigt alle neuen Kandidaten (Spalte `Quelle`: Marke, kunzer.de, GenArt, Titel, KI) mit Haekchen zur Auswahl; `Uebernehmen` haengt die angehakten Suchwoerter an die vorhandenen an und speichert. Laeuft gerade ein Hintergrundvorgang (z. B. die Attribut-Findung), erscheint der Dialog sofort nur mit den Regel-Kandidaten und einem Hinweis - spaeter erneut druecken holt die KI-Vorschlaege nach.
- **KI-Vorschlaege** (Einstellungen > `API` > `Suchwoerter per KI vorschlagen`, Standard an, wirksam nur mit Claude API Key): bis zu 10 Begriffe, wie Werkstaetten und Haendler im Teilekatalog suchen - Synonyme, Umgangssprache, Produktgattung, Einsatzzweck; keine Marken- oder Artikelnummern, keine Saetze, je maximal 35 Zeichen. Nach dem Kunzer-Laden laufen sie als Nachlauf hinter der automatischen Attribut-Findung und werden ohne Rueckfrage angehaengt und gespeichert (Statuszeile nennt die Anzahl); beim Button landen sie mit im Auswahldialog. Die KI bekommt den Produkttext als reinen Inhalt; ihre Vorschlaege werden lokal nachgeprueft (Laenge, keine Artikelnummer/Marke, keine Dubletten).
- **Dubletten**: Vergleich ohne Gross-/Kleinschreibung, Umlaute, Bindestriche und Leerzeichen (`T D L` = `TDL`, `Reifen-Dichtmittel` = `Reifendichtmittel`); Terme ueber 35 Zeichen (bis v0.1.57: 50) oder nur aus der Artikelnummer entfallen.
- **Massenimport**: je Artikel werden die Regel-Kandidaten gesammelt und am Ende des Laufs in EINEM Schreibvorgang (Modus `Ergaenzen`, wie der Datei-Import) in die `Gebrauchsnummern.xlsx` geschrieben; vorhandene Suchwoerter bleiben. KI-Vorschlaege gibt es im Massenimport nur mit `Suchwoerter per KI auch im Massenimport` (Standard aus); vor dem Start zeigt die App die geschaetzten Kosten und fragt nach. Das Abschlussfenster nennt die Anzahl der ergaenzten Suchwoerter; KI-Fehler je Artikel stehen in der Warnungsliste.

## TecDoc Anhangsformattyp ID

Die Exportdateien fuer Bilder, Dokumente, Videos und Web Links enthalten zusaetzlich die Spalte `TecDoc Anhangsformattyp ID`.

Aktuelle Zuordnung:

- `JPG` und `JPEG` -> `3`
- `PNG` -> `6`
- `PDF` -> `2`
- `GIF` -> `7`
- jede `http/https` URL -> `4`

Das gilt jetzt bewusst auch dann, wenn eine URL auf `.png`, `.jpg`, `.jpeg` oder `.pdf` endet. Nur lokale/dateibasierte Pfade werden noch ueber die Dateiendung typisiert.

Wenn fuer einen Anhang kein unterstuetztes Format erkannt wird, bricht der Export mit einer klaren Fehlermeldung ab, damit keine fehlerhaften Importdateien entstehen.

## DeepL

Der API Key wird bewusst nicht fest im Quellcode gespeichert. Du kannst ihn in der GUI eintragen oder vor dem Start als Umgebungsvariable setzen:

```powershell
$env:DEEPL_API_KEY="dein-key"
python apollo_import_gui.py
```

Standardmaessig nutzt die GUI `https://api.deepl.com`. Fuer DeepL Free kannst du in der GUI oder per `DEEPL_API_BASE_URL` auf `https://api-free.deepl.com` wechseln.

## Hinweis

Die GUI kann auf zwei Arten exportieren:

- mit Zeitstempel-Unterordner, damit alte Exporte erhalten bleiben
- direkt in einen festen Ausgabeordner, damit immer derselbe Importpfad genutzt werden kann

Im festen Ausgabeordner bleiben die 14 Exportdateien (siehe `Exportierte Dateien`) bestehen. Neue Artikel werden angehaengt, und bei erneutem Export derselben Artikelnummer werden nur die alten Zeilen dieses Artikels ersetzt.
Bei einer neuen Artikelnummer werden die `Text Modul ID`s automatisch im bestehenden 6-stelligen Format erzeugt und gegen vorhandene IDs geprueft. Bestehende Artikel behalten ihre bereits gespeicherten IDs.

Die Output-Dateien dienen dabei als Live-Datenbank: Aenderungen an Texten, Bildern, Dokumenten, Videos und Links werden aus der GUI direkt in diese Excel-Dateien zurueckgeschrieben.

## Kompaktlayout

Die GUI ist jetzt auf kleinere Displays wie 14-Zoll-Laptops ausgelegt:

- im Projekt-Tab werden `Artikel`, `Export`, `APIs` und `Artikelverzeichnis` bei schmalerer Breite automatisch untereinander angeordnet
- `Artikel`, `APIs` und `Artikelverzeichnis` koennen direkt eingeklappt und wieder eingeblendet werden
- die Vorschauen in `Bilder`, `Dokumente`, `Videos` und `Web Links` lassen sich ausblenden und werden bei wenig Breite automatisch unter die Tabelle verschoben
- diese Sichtbarkeits-Einstellungen werden zusammen mit dem restlichen GUI-Zustand gespeichert

## Updates

Im Projekt-Tab gibt es einen Bereich `App-Update`.

- `Nach Updates suchen` fragt das neueste GitHub-Release des Repositories ab
- wenn ein neueres Release gefunden wird, laedt die GUI bevorzugt ein `Setup`- oder `onefile`-Paket herunter
- laeuft die Anwendung bereits als gebaute Windows-EXE, kann sie sich selbst schliessen, die EXE ersetzen und danach automatisch neu starten
- wenn die GUI aus dem Python-Quellcode gestartet wurde, wird die Release-Datei nur heruntergeladen und der Ordner geoeffnet
